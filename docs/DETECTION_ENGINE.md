# Detection Engine

Silnik analizuje ręcznie przekazany tekst/adres regułami lokalnymi, korzysta z lokalnych list reputacji, zbiera wybrane snapshoty systemu i zapisuje zdarzenia w SQLite. Zdarzenia mają źródło, kategorię, ryzyko, wyjaśnienie, rekomendację, status oraz dostępne dowody/kody reguł. Zdarzenia domenowe i procesowe mogą być grupowane po lokalnych identyfikatorach korelacji.

Ręczna analiza tekstu/URL używa centralnego `RiskEngine`, który zwraca wynik heurystyczny 0–100 i poziom w `ThreatAssessment`. Wynik wynika z wag różnych wskaźników i ich liczby; nie jest prawdopodobieństwem ani kalibracją na niezależnym holdoucie. SQLite v41 utrwala go w ręcznych zdarzeniach i eksportach, a Agent może przekazać go do usługi. Monitory procesu, TCP, DNS, persistence i Downloads używają też `EvaluateEvidenceCodes`, który punktuje wyłącznie jawne kody dowodów. Nieznane kody są ignorowane; sam lokalny hash z niezweryfikowanej listy nie uzyskuje wyniku numerycznego. `RiskScore` i `RiskLevel` są zapisywane razem. Ocena nadal jest heurystyczna, bez niezależnej kalibracji.

Nowe PID-y z procesu snapshotu są korelowane z jednym udokumentowanym snapshotem Toolhelp. Reguła `process.behavior.office-spawned-script-host` oznacza uruchomienie interpretera/skryptu przez proces Office jako umiarkowane ryzyko wymagające sprawdzenia. Wyjaśnienie zawiera nazwy i PID-y zaobserwowanej relacji. Krótkie procesy oraz rodzice zakończeni przed snapshotem mogą zostać pominięci; heurystyka nie dowodzi ataku, a Sentinel nie zatrzymuje procesu.

Po asynchronicznym obliczeniu obrazu procesu Engine łączy jego rekord z najbliższym czasowo, kompatybilnym dopasowaniem nowego pliku Downloads, jeśli SHA-256 jest identyczny, a czas obu zdarzeń różni się o nie więcej niż 10 minut. Historia zachowuje wspólny `CorrelationId` i dowód `correlation.download-process.same-sha256`; różny hash, nieodczytany hash, zdarzenie poza oknem albo wcześniejsza korelacja z innym incydentem pozostają niepowiązane. Engine łączy jeden najbliższy rekord, aby nie scalać niezależnych pobrań o tym samym hashu. Jest to korelacja dwóch lokalnych obserwacji, nie dowód, że proces uruchomiono bezpośrednio z konkretnej ścieżki pobrania. Wymaga wcześniejszego dopasowania pliku do lokalnej listy hashy.

Jeśli proces ma dowód `process.behavior.office-spawned-script-host`, nowy TCP tego samego PID w ramach 60-sekundowego `CorrelationId` jest zapisywany jako powiązana, umiarkowana heurystyka z kodem `correlation.process-network.office-spawned-script-host`. Zwykłe nowe TCP pozostaje informacyjne; dopasowanie IP do lokalnego feedu zachowuje osobny, silniejszy sygnał zależny od pochodzenia listy. Jest to korelacja metadanych po PID i czasie, nie analiza pakietów ani dowód złośliwości; Sentinel nie blokuje ruchu. Test obejmuje heurystyczny start procesu i późniejszy snapshot TCP w tym samym incydencie.

Analiza AI przez lokalną Ollama jest opcjonalna i wymaga ręcznej konfiguracji; brak modelu nie wyłącza reguł. Wynik modelu nie jest skalibrowanym prawdopodobieństwem. Monitorowanie procesów i zmian nie jest równoważne detekcji zachowania malware. Nie ma zintegrowanej blokady wykonania ani WFP. Dla nowego pliku z Downloads, który pasuje do ręcznie zaimportowanej listy SHA-256, użytkownik może jawnie uruchomić odwracalne przeniesienie do lokalnej kwarantanny; hash jest weryfikowany ponownie przed i po przeniesieniu. To dopasowanie nie potwierdza złośliwości, nie obejmuje innych plików/źródeł, a Sentinel nie wykonuje tej akcji automatycznie. Użytkownik nie powinien otrzymać komunikatu o zablokowanym zagrożeniu bez potwierdzonej blokady.

Brak dopasowania reputacji, brak alertu lub podpis Authenticode nie dowodzą bezpieczeństwa/złośliwości. Każda automatyczna reakcja o nieodwracalnym skutku pozostaje poza zakresem.
