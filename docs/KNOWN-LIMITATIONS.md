## Analiza i źródła zdarzeń

- Ręczna analiza URL/tekstu używa lokalnych reguł i ograniczonych heurystyk (`2026.10.10`); nowa wersja normalizuje wybrane defangowane zapisy hosta wyłącznie w pamięci. 32 jawnie syntetyczne przypadki (15 TP, 17 TN), regresje brandowych domen i mieszanych IDN dotyczą wcześniejszego zestawu reguł; defangowanie ma osobne testy jednostkowe, ale nie zostało zmierzone na niezależnym zbiorze. Eksploracyjna ewaluacja całego UCI PhiUSIIL (URL-only, bez holdoutu i deduplikacji) dała recall 4,3222%, precision 99,8855% i FPR 0,0037% przy progu Moderate. Większość phishingowych adresów nadal nie wywołała alarmu; ten zbiór był wcześniej eksplorowany, więc wynik nie jest niezależną ani produkcyjną miarą. Confidence pozostaje puste bez kalibracji. Metoda i reprodukcja: [DETECTION-EVALUATION.md](DETECTION-EVALUATION.md).
- Dodatkowy domenowy holdout Mendeley Phishing URL v1 dla zamrożonych reguł `2026.10.9` dał TP=439, FP=2 629, TN=16 962, FN=13 102 (precision 14,31%, recall 3,24%, FPR 13,42%). Interpretacja jest warunkowa, bo mapowanie etykiet `0=benign, 1=phish` wywnioskowano z liczebności zgodnych z kartą zbioru; ten wynik nie był użyty do strojenia i nie reprezentuje ruchu produkcyjnego. Badawczy klasyfikator znakowych n-gramów także nie został wdrożony: na oficjalnych benchmarkach przy bazie phishingu 0,05% jego średnia precision wyniosła 13,715% przy kalibracji do FPR 0,1%. Obecne dowody nie uzasadniają alarmów produktowych dla nieznanych URL-i. Szczegóły, metody i ograniczenia: [ewaluacja detekcji](DETECTION-EVALUATION.md).
- Ekran ręcznej analizy ostrzega, że brak alarmu nie potwierdza bezpieczeństwa, a Sentinel nie blokuje stron i nie zastępuje Defendera. Historyczny pomiar PhishVN v3.1.0 dla reguł `2026.10.6` wykrył 0/487 phishingowych URL-i w podzbiorze testowym gold/silver. Nie powtórzono tego benchmarku dla `2026.10.10`; obsługa defangowania nie rozwiązuje ogólnego niskiego recall. To wynik konkretnego zbioru, nie przewidywanie skuteczności dla wszystkich adresów.
- Lista CERT Polska wymaga ręcznego pobrania, wygasa po 48 godzinach i dotyczy domen. Reputacja IP jest dostępna tylko dla jawnie zaimportowanej przez użytkownika listy IP/CIDR i nowych połączeń TCP przy włączonym monitoringu; Sentinel nie weryfikuje źródła ani licencji tej listy. Nie ma automatycznego feedu IP, pokrycia UDP ani reputacji pełnych URL-i malware; URLhaus nie jest podłączony.
- Cache DNS Windows jest próbkowany, a nie odczytywany jako strumień zapytań. Read-only parser/reader zdarzenia 3008 z kanału `Microsoft-Windows-DNS-Client/Operational` wdrożono dla kanału, który jest już włączony; nie zapisuje on odpowiedzi DNS. Na maszynie audytu kanał jest wyłączony, więc zweryfikowano tylko fallback, a nie live odczyt zdarzeń. Sentinel kanału nie włącza. DoH, VPN, zapytania po IP oraz wpisy usunięte między próbkami mogą zostać pominięte.
- Procesy są próbkowane lokalnie co około sekundę; opt-in monitoring TCP/UDP również odpyta tabele Windows co około sekundę. Krótkie procesy lub połączenia mogą zakończyć się między próbkami. SQLite v38 (backlog wprowadzony w v36) przechowuje nadmiar zmian procesów po limicie 100 na próbkę w backlogu do 20 000 pozycji i ponawia je po restarcie; zmiany przekraczające ten limit są trwale zliczane w SQLite, ale mogą nie trafić do historii. Tabele są ograniczone do 10 000 procesów, 800 wpisów TCP i 200 UDP; niepełne próbki wstrzymują niepewne alerty. UDP pokazuje lokalny endpoint, nie potwierdza datagramu ani nie ujawnia zdalnego celu. Nie ma gwarantowanego event stream: próby WMI i sesji ETW wymagały dostępu systemowego, którego konto audytu nie miało.
- Nie ma WFP, sterownika jądra, filtrowania ani automatycznego blokowania ruchu. Sentinel nie przechwytuje payloadu HTTPS ani nie instaluje certyfikatu do inspekcji TLS.
- Monitoring Downloads jest opt-in i obejmuje nowe/zmienione pliki w podfolderach do 256 MiB na plik; nie skanuje plików istniejących przed włączeniem. Odrzuca reparse point w root i podkatalogach, a pełne uzgodnienie baseline'u wykonuje co 5 minut (limit 100 000 plików). Testy wymuszonej podmiany rootu przed odczytem oraz startowego rootu będącego junctionem przechodzą; 100 kontrolowanych wyścigów i współbieżny stress test 40 przełączeń junctionu również przeszły bez odczytu/alertu dla pliku zewnętrznego. Rzeczywiście przekierowany Known Folder pozostaje nieprzetestowany. Porównanie SHA-256 działa lokalnie z listą importowaną przez użytkownika. Nazwy/ścieżki, rozmiary i czasy plików są zapisywane lokalnie bez szyfrowania. Brak dopasowania nie oznacza bezpieczeństwa.
- Ręczny skan pliku liczy SHA-256 i sprawdza status Authenticode. Opcjonalny MalwareBazaar lookup wysyła wyłącznie hash po osobnym kliknięciu i wymaga klucza API; nie został sprawdzony z rzeczywistym kluczem. Warunki komercyjnego użycia zależą od dostawcy.
- Ollama wymaga osobnej instalacji, lokalnego modelu i jawnego włączenia; nie zweryfikowano jej na rzeczywistym modelu. Read-only sprawdzenie 2026-10-25 nie znalazło lokalnego polecenia/procesu, a API `127.0.0.1:11434` nie odpowiedziało w 2 s; nie wykonano żądania modelowego ani pobierania. Baza wiedzy obsługuje pełne wyszukiwanie semantyczne po wszystkich fragmentach przy użyciu osobno wybranego lokalnego modelu embeddingowego; indeks jest lokalny, a przy braku modelu lub błędzie działa wyszukiwanie FTS5. Jakości wyszukiwania nie zmierzono na reprezentatywnej bazie. PDF bez warstwy tekstowej wymagałby OCR, którego nie ma.

## Enterprise, dane i prywatność

- Monitoring trwałości Windows jest opt-in i obejmuje HKCU/HKLM Run/RunOnce (widoki 32/64-bit), bezpośrednie pliki Startup użytkownika/wspólnego Startup, Scheduled Tasks przez `schtasks /query /xml` oraz usługi i sterowniki z `HKLM\SYSTEM\CurrentControlSet\Services`. Dla usług/sterowników hashuje wybrane wartości konfiguracji; nazwy, polecenia i ścieżki nie są zapisywane. Trwały, zredagowany baseline wykrywa różnice przy kolejnej próbce/restarcie, ale nie wykrywa zmian dodanych i cofniętych podczas zamknięcia. Odczyt zadań może wymagać dodatkowych uprawnień; przy odmowie monitor zachowuje poprzedni baseline i raportuje ograniczenie. Live test odczytu rejestru nie przeszedł w ograniczonym środowisku (`SecurityException`); nie zmieniano uprawnień. Snapshot jest ograniczony do 1024 elementów łącznie, a odczyt zadań do 8 MiB; większy lub nieprawidłowy snapshot wstrzymuje próbkę. Cichy baseline nie alarmuje o stanie zastanym przy pierwszym dostępie. Reguła lokalizacji jest heurystyczna.

- Serwer Enterprise jest osobnym projektem. Wdrożenie poza loopback wymaga HTTPS z certyfikatem zaufanym przez Windows; repozytorium nie dostarcza publicznego serwera ani zaufanego certyfikatu. Instalator serwera nie konfiguruje TLS ani zapory.

# Process image inspection

Process start monitoring is snapshot-based and may miss processes shorter than the polling interval. Process changes are buffered in the current SQLite v38 schema (backlog introduced in v36) capped at 20,000 and drained at 100 per sample; overflow beyond the cap is counted but may be omitted. Image paths can be unavailable due to Windows access restrictions, and delayed start events from the backlog intentionally omit the image path to avoid attributing a later process that reused the PID. Background SHA-256 and Authenticode inspection is limited to 256 MiB and a queue of 33 (including one in-flight item); excess work is marked `QueueFull` and pending work is retried after engine restart. Local hash comparison only reflects a user-imported feed. An absent match is not a clean verdict, and an unsigned file is not by itself malware. Paths and hashes are stored in local history and are omitted from JSON/CSV exports and Enterprise payloads. WMI/ETW event-stream collection is not implemented because the tested account lacked access.
