# Monitorowanie Windows — zakres

Monitorowanie jest lokalne; konkretne stany zależą od ustawień, platformy i uprawnień. `Sentinel.Agent` w sesji użytkownika wywołuje `collect` w `Sentinel.Engine` mniej więcej co sekundę, niezależnie od otwartego okna Electron. To cykliczne zbieranie obsługiwanych migawek i zdarzeń, a nie pełny strumień telemetrii systemowej.

Repozytorium zawiera też `Sentinel.Service`, uruchamiany przez Windows SCM jako `LocalService`, oraz nowy helper UAC instalatora. Usługa cyklicznie wywołuje własny Engine i zapisuje stan w osobnym ProgramData; UI odczytuje jej heartbeat przez potok o ograniczonym SID, oddzielnie od statusu Agenta. Nowy przepływ instalatora czeka na Windows CI. Usługa i Agent nadal mają osobne silniki/bazy i mogą powtarzać część monitorów; zdarzenia użytkownika nie są jeszcze przekazywane do usługi.

W **nowym profilu** monitorowanie jest domyślnie aktywne dla procesów, pobranych plików, zmian autostartu/trwałości i połączeń TCP/UDP. Dane są lokalne. Istniejące, zapisane preferencje pozostają bez zmian; wstrzymanie ochrony nadal zatrzymuje odpowiednie źródła. Zbieranie tekstu aktywnego okna i automatyczne pobieranie zewnętrznych list pozostają wyłączone.

- **Procesy:** snapshoty PID/nazw co około sekundę. Dla nowych procesów odczytywana jest jedna migawka Toolhelp z PID-ami rodziców; reguła oznacza relację Office → interpreter/host skryptów jako wymagającą sprawdzenia, nie jako potwierdzone zagrożenie. Zdarzenie zawiera nazwę i PID rodzica w lokalnym wyjaśnieniu. Zależność od próbkowania oznacza, że krótkie procesy lub zakończony proces rodzic mogą zostać pominięte; korelacja PID nie jest pełnym strumieniem ETW. Obrazy procesów są analizowane w ograniczonej kolejce SHA-256/Authenticode.
- **Pobrane pliki:** `FileSystemWatcher` i uzgadnianie w folderze Downloads; domyślnie włączone dla nowych profili. Porównanie SHA-256 dotyczy tylko lokalnie zaimportowanej listy. Brak dopasowania nie oznacza czystego pliku.
- **Autostart/trwałość:** snapshot rejestru Run/RunOnce, Startup, Scheduled Tasks i wybranych ustawień usług/sterowników; domyślnie włączone dla nowych profili, różnicowy baseline i możliwe odmowy dostępu. Nie jest to strumień zdarzeń ciągłych.
- **Sieć:** snapshot TCP/UDP próbkowany cyklicznie; domyślnie włączony dla nowych profili. Krótkie połączenia mogą zostać pominięte; treść i pełny URL nie są odczytywane.
- **DNS:** cache systemu odczytywany przez `ipconfig /displaydns`; kanał DNS Client Operational odczytywany tylko gdy jest dostępny/włączony. Nie obejmuje wiarygodnie DoH, DoT, VPN ani zapytań wyłącznie po IP i nie przypisuje DNS do procesu.
- **Windows Security Center:** Engine odczytuje lokalny, zagregowany stan kategorii antywirusa i zapory przez [`WscGetSecurityProviderHealth` (Microsoft Learn)](https://learn.microsoft.com/en-us/windows/win32/api/wscapi/nf-wscapi-wscgetsecurityproviderhealth), z cache jednej minuty. API nie identyfikuje konkretnego produktu ani jego wersji sygnatur. Sentinel niczego tu nie włącza/wyłącza i nie zastępuje Defendera.
- **Microsoft Defender:** Engine co 5 minut uruchamia w tle wbudowany `Get-MpComputerStatus` ([Microsoft Learn](https://learn.microsoft.com/en-us/powershell/module/defender/get-mpcomputerstatus)) i odczytuje wyłącznie `AntivirusEnabled`, `RealTimeProtectionEnabled`, wersję, wiek i czas aktualizacji sygnatur. Przy niedostępności ponawia najwyżej co 15 minut. Zapytanie ma limit 4 s, nie zmienia ustawień i nie przesyła danych. Brak modułu, odmowa lub timeout daje jawny stan niedostępny. Na bieżącym środowisku testowym cmdlet zwrócił `Access denied` bez podnoszenia uprawnień; tego odczytu nie uznajemy za PASS na typowym profilu. Jest to status samego Defendera; WSC nadal określa zagregowany stan wszystkich dostawców i może raportować inny antywirus.
- **ETW/WMI, WFP:** testowane źródła 4688/ETW nie są dostępne w typowym koncie testowym; WFP jest niewdrożone.
- **Powiadomienia:** agent pokazuje balonik zasobnika dla dopasowań reputacji i wybranych relacji procesów, z limitem jednego alertu na typ na 10 minut i krótkim lokalnym tonem. Dopasowania lokalnych list SHA-256/IP o niezweryfikowanym źródle używają tonu informacyjnego; DNS, WSC i heurystyki używają ostrzegawczego. Zgrupowane alerty wybierają najwyższą wagę. Nie jest to powiadomienie o zablokowanym zagrożeniu; mechanizm blokowania nie istnieje.

## Ręczne sprawdzenie z menu Eksploratora

Instalator rejestruje per-user polecenie `Sprawdź w Sentinel AI` dla zaznaczenia obejmującego maksymalnie 15 plików. W Windows 11 klasyczne polecenie może być dostępne pod „Pokaż więcej opcji”. Explorer przekazuje żądania do jednej instancji aplikacji; Sentinel scala je, sprawdza każdy plik lokalnie i pokazuje jeden zbiorczy wynik. Nieprawidłowe, opcjopodobne i nadmiernie długie ścieżki są odrzucane. Analiza oblicza SHA-256 i odczytuje stan Authenticode; nie wykonuje pliku, nie przesyła go do usługi zewnętrznej i nie blokuje go. Wynik rozróżnia dopasowanie do lokalnej listy od braku dopasowania i nie stanowi werdyktu, że plik jest bezpieczny. Wpis jest weryfikowany i usuwany tylko wtedy, gdy polecenie nadal wskazuje na plik Sentinel z danej instalacji.
