# PLAN-013 — lokalna reputacja dokładnych URL

1. **Cel:** umożliwić użytkownikowi lokalne dopasowanie wklejonych i przeglądarkowych adresów do jawnie dostarczonej listy URL, bez wysyłania analizowanego adresu do źródła listy.
2. **Stan obecny:** `UrlReputation` przyjmuje UTF-8 TXT z jednym HTTP/HTTPS URL na wiersz, ignoruje puste i `#` komentarze, normalizuje fragmenty, zapisuje tylko SHA-256 w osobnej bazie SQLite, wspiera atomic replacement, rollback, clear i status ważności 48 h. Core, matcher, Store, browser response i Engine IPC są podłączone. Feed nie jest pobierany automatycznie ani weryfikowany przez Sentinel.
3. **Braki:** właściciel musi sam ocenić pochodzenie, datę i prawa do listy. Nie ma kuratorowanego feedu phishingowego ani niezależnego pomiaru detekcji wynikającego z tego importu. PhishVN URL-only dla heurystyk bez feedu nadal ma recall 0% (0/487 test). Próbkowanie i hash nie są dowodem, że lista jest prawdziwa lub bezpieczna. Przegląd źródeł: Google Safe Browsing dopuszcza użycie API tylko niekomercyjne, a komercyjny Google Web Risk rozlicza lookup po przekroczeniu bezpłatnego limitu; wymagałby decyzji o kluczu, zgodzie na przekazywanie URL i budżecie. URLhaus gromadzi adresy dystrybucji malware, nie phishing, więc nie zamyka luki F03. ([Safe Browsing](https://developers.google.com/safe-browsing/?csw=1), [Web Risk pricing](https://cloud.google.com/security/products/web-risk), [URLhaus policy](https://urlhaus.abuse.ch/api/))
4. **Decyzje architektoniczne:** dopasowanie dokładnego znormalizowanego URL; fragment `#` pominięty, ścieżka/query zachowane. Odrzuć cały import przy niepoprawnym wpisie. Import jest lokalny, ograniczony do 20 MiB, 250 000 wpisów i 500 000 wszystkich linii; duplikaty nie omijają limitu wpisów. Wynik ma kod `reputation.url-feed` i podnosi ryzyko co najmniej do High, ale nie obniża Critical. Nie loguj ani nie eksportuj URL, hosta lub sygnałowego hasha.
5. **Zależności:** istniejące SQLite/Engine IPC, Native Messaging i okno wyboru pliku; bez nowej zależności runtime i bez klucza zewnętrznego.
6. **Etapy:** (a) parser i ograniczenia — wdrożone; (b) atomowy magazyn, rollback i clear — wdrożone; (c) matcher manual/browser i hash sygnału — wdrożone; (d) UI importu/statusu/rollback/clear — wdrożone; (e) prywatność i Engine IPC — testy wdrożone; (f) test instalatora GUI nowego buildu — oczekuje na potwierdzenie użytkownika, ponieważ pierwotnie potwierdzony hash nie odpowiada aktualnemu plikowi; (g) jeśli przyszły feed zewnętrzny zostanie rozważony, najpierw zweryfikować komercyjne warunki, licencję redystrybucji, prywatność lookupów i metodę aktualizacji.
7. **Pliki:** `src/Sentinel.Core/Analysis/UrlReputation.cs`, `ManualUrlReputationMatcher.cs`, `Sentinel.Engine/Program.cs`, `Sentinel.UrlHost/UrlRequestProcessor.cs`, `desktop/electron/main.cjs`, `desktop/src/main.tsx`, testy `UrlReputationTests`, `ManualUrlReputationMatcherTests`, `StoreTests`, `BrowserIntegrationTests` i `scripts/test-engine.cjs`.
8. **Prywatność:** baza bieżąca/przywracana przechowuje SHA-256 URL, nie surowe wartości. Metadata `version` to SHA-256 całego pliku źródłowego, bez surowych linii. Historia i Enterprise nie przyjmują URL/hosta/hash; feed nie wykonuje ruchu sieciowego.
9. **Testy:** exact match i bliskie non-match ścieżki/query, normalizacja fragmentu/default port/hosta, wygasły feed, niepoprawny/empty import zachowujący poprzedni stan, rollback, clear, redakcja DB i historii, browser odpowiedź, deduplikacja korelacji i Engine IPC. Regresja limitu obejmuje ponad 250 000 powtórzonych wpisów i ponad 500 000 komentarzy.
10. **Kryteria akceptacji:** brak automatycznej transmisji URL; błędny feed nie zastępuje poprawnego; powyżej limitu nic nie zostaje zaimportowane; dopasowanie daje High; niepasujący dokładny URL nie zostaje podniesiony przez sam host; brak surowych URL w DB/historii/odpowiedzi; rollback/clear są atomowe.
11. **Ryzyka i ograniczenia:** źródło może być przestarzałe, błędne lub nielegalnie użyte; hash jest pseudonimizacją, nie szyfrowaniem. Dokładne URL-e nie wykrywają nieznanych kampanii, nowych URL-i, przekierowań ani zmiennej treści. Aktualny wynik PhishVN testu dla heurystyk offline pozostaje 0/487 i nie jest poprawiany przez lokalny feed.
