Read-only `SHGetKnownFolderPath` zwróciło `C:\Users\Mateusz\Downloads`, identyczne z domyślną ścieżką profilu; konto nie ma obecnie przekierowanego Downloads, więc rzeczywisty test przekierowania pozostaje otwarty.

1. **Cel:** na jawne żądanie oceniać wybrany plik przez hash, podpis i audytowane źródło reputacji.
2. **Stan obecny:** `Sentinel.Engine` na jawne żądanie otwiera wybrany plik do 256 MiB tylko do odczytu, liczy SHA-256, zwraca status Authenticode i sprawdza dokładne dopasowanie do lokalnej listy hashy zaimportowanej przez użytkownika. Opcjonalny lookup MalwareBazaar wysyła wyłącznie SHA-256 po osobnym kliknięciu; osobisty Auth-Key jest chroniony DPAPI. Dodatkowy, domyślnie wyłączony watcher katalogu `Downloads` bada nowe i zmienione pliki w podkatalogach względem lokalnego feedu, nie podąża za reparse points, wykonuje okresowe uzgodnienie drzewa co 5 minut, nie wykonuje lookupów sieciowych i zapisuje lokalne zdarzenie tylko przy dopasowaniu. Limit baseline'u wynosi 100 000 plików; pauza zatrzymuje watcher i czyści baseline. Brak dopasowania w którymkolwiek źródle nie jest werdyktem bezpieczeństwa.
3. **Braki:** niezależne źródło i świeżość lokalnego feedu, test z autoryzowanym kluczem przeciw prawdziwemu API oraz wielominutowy stress soak. Kontrola rootu oraz finalnej ścieżki uchwytu przed i po hashowaniu odrzuca podmianę rootu lub parenta na reparse point przed odczytem; root jest otwierany przez `FILE_FLAG_OPEN_REPARSE_POINT`. Deterministyczny test obejmuje root, 100 podmian parenta oraz współbieżny pseudolosowy stress 160 przełączeń junctionu (ziarno 0x5E17, opóźnienia 1–5 ms) PASS lokalnie 1/1; poprzednie deterministyczne stressy również PASS. Przekierowany Known Folder zweryfikowano osobno w CI 1/1; oczekuje na CI nowa wersja stressu, a wielominutowy soak nadal pozostaje otwarty. Trwałe wznowienie obserwacji nowych i zmienionych plików po restarcie silnika wdrożono w v0.15.23. v0.15.25 automatycznie ponawia start watchera podczas kolejnego collect po przejściowym błędzie bazy. W v0.15.19 watcher odtwarza w aktywnej sesji overflow kolejki/bufora; v0.15.20 ogranicza stan do 100 000 plików i zatrzymuje monitoring po osiągnięciu limitu. Pliki obecne przed pierwszym włączeniem nie są hashowane.
4. **Decyzje:** ręczny skan i jawne lookup; brak automatycznego odczytu prywatnych katalogów; brak uploadu/próbkowania plików. MalwareBazaar community API wymaga Auth-Key i jest domyślnie nieaktywne; przed użyciem należy zapoznać się z [warunkami dostawcy](https://bazaar.abuse.ch/api/), ponieważ zastosowanie komercyjne może wymagać płatnego API. Lokalny feed pozostaje dostępny offline.
5. **Zależności:** podpis Authenticode/WinVerifyTrust, osobisty Auth-Key i zgodność z warunkami źródła, model zdarzeń.
6. **Etapy:** (a) ograniczenie rozmiaru, uchwyt tylko do odczytu i TOCTOU — wdrożone; (b) sprawdzenie Authenticode przez izolowany Windows PowerShell bez ładowania profili — wdrożone; (c) lokalny provider dokładnych SHA-256 z limitem 20 MiB/250 000 wpisów i atomową walidacją — wdrożony; (d) ręczny wybór pliku do skanu, import i potwierdzane usunięcie feedu z UI — wdrożone; (e) ręczny hash-only lookup MalwareBazaar, stały HTTPS endpoint, klucz DPAPI, UI zgody i testy mock HTTP — wdrożone; (f) ograniczony watcher Downloads z opt-in, lokalnym dopasowaniem, Known Folder resolverem, rekursją bez podążania za reparse points, cyklicznym uzgodnieniem podfolderów, reconciliacją overflow i bounded SQLite v9 baseline z restart recovery — wdrożone; (g) prawdziwy lookup z autoryzowanym kluczem i test rzeczywiście przekierowanego Known Folder — pozostają.
7. **Pliki:** engine file case, nowy core file analyzer/provider, UI, testy.
8. **Prywatność:** hash jest pseudonimizującym identyfikatorem; sieć nie jest używana bez osobnego kliknięcia; request zawiera hash i Auth-Key, bez nazwy/ścieżki/pliku. Przy opt-in monitorze Downloads pełne ścieżki, rozmiary i czasy modyfikacji są lokalnie zapisane w nieszyfrowanej bazie, aby wznowić obserwację po restarcie; nie są wysyłane. Klucz jest chroniony DPAPI CurrentUser i można go usunąć w UI.
9. **Testy:** .NET obejmuje lokalne dopasowanie oraz mock API: wynik znany, `no_results`, odrzucenie błędnego hasha i niezgodnego hashy w odpowiedzi. Test sprawdza stały host i wyłącznie form fields `query`/`hash`. Engine IPC sprawdza prawdziwy podpis Authenticode `Valid` na systemowym PowerShell, zmodyfikowaną kopię o statusie innym niż `Valid`, niepodpisany fixture, lokalny feed/scan, odrzuca sparse plik 256 MiB + 1 bajt przed hashowaniem, a na izolowanym katalogu Downloads potwierdza zdarzenie lokalnego dopasowania i brak zdarzeń po wyłączeniu lub pauzie. Testy .NET sprawdzają przepełnienie kolejki z nowym plikiem w podfolderze, brak skanowania plików sprzed włączenia, okresowe uzgodnienie po usunięciu całego podfolderu, fail-closed limity baseline'u, restart, reset przy pauzie/wyłączeniu, cleanup ścieżek i retry po błędzie bazy. Test migracji v8→v9 zachowuje historię.
10. **Akceptacja:** brak listy lub brak dopasowania nigdy nie daje „bezpieczny”; UI opisuje źródło i ryzyko komercyjnych warunków; lookup jest jawny i hash-only; import lokalny jest atomowy i ograniczony.
11. **Ryzyka:** podpis legalny nie dowodzi bezpieczeństwa; nieznany plik nie dowodzi malware; feed ma licencję/false positive.
12. **Status:** `IN_PROGRESS` — ręczne SHA-256/Authenticode, lokalna lista hashy, opcjonalny hash-only lookup MalwareBazaar i watcher Downloads po opt-in są wdrożone. Zmiana obejmuje podfoldery, pomija reparse points, a uzgodnienie drzewa co 5 minut naprawia pominięte zdarzenia i usuwa nieaktualne ścieżki. `DownloadedFileMonitorTests` 14/14 lokalnie PASS, w tym root junction, 100 deterministycznych podmian parenta oraz 160 pseudolosowych przełączeń (lokalnie targeted 1/1, 8 s).
