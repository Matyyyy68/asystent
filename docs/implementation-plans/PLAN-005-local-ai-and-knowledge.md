# PLAN-005 — lokalne AI i baza wiedzy

1. **Cel:** aktywna aplikacja używa opcjonalnie istniejącego Ollama provider i lokalnej FTS5 KB po jawnym kliknięciu.
2. **Stan obecny:** `AIProviders.cs` ma loopback allowlist, limity, prompt-injection guard, JSON validation i fallback; `LocalKnowledgeBase` importuje TXT/MD/DOCX oraz tekstowe PDF (do 10 MB, 500 stron i 2 mln znaków; bez OCR). DOCX jest strumieniowany przez `XmlReader`, respektuje anulowanie, limituje wyjście w trakcie ekstrakcji i odrzuca DTD/encje zewnętrzne. Aktywne Engine/UI udostępniają listę modeli, jawne opt-in, import/search/delete KB, a `AnalysisOrchestrator` przekazuje trafienia FTS5 do modelu jako niezaufany kontekst.
3. **Braki:** pełne semantyczne wyszukiwanie niezależne od FTS5, OCR PDF, reprezentatywny pomiar trafności źródeł, testy UI i weryfikacja rzeczywistego modelu. Dodano opcjonalne semantyczne porządkowanie maksymalnie 20 kandydatów znalezionych przez FTS5; nie odnajduje ono dokumentów poza wynikami leksykalnymi. Kontrolowany benchmark regresyjny czterech zapytań na syntetycznych dokumentach sprawdza Hit@3=100% i MRR=1,00, ale nie mierzy jakości na rzeczywistej bazie wiedzy. Wyszukiwanie rozszerza też długie tokeny dokładnym dopasowaniem lub prefiksem obciętym o trzy znaki, co pomaga części polskich odmian, ale może zwrócić szersze dopasowania i nie jest lematyzacją. Wskaźnik odpowiedzi AI może cytować wybrane przez model fragmenty z numerowanej listy FTS5; walidacja potwierdza, że cytat pochodzi z bieżącego kontekstu, ale nie dowodzi, że tekst go uzasadnia.
4. **Decyzje:** wyłącznie loopback; model nigdy nie uruchamia narzędzi; analiza pozostaje regułowa przy awarii; import wybierany przez usera; semantyczne porządkowanie jest opcjonalne i wymaga osobno wybranego modelu embeddingowego.
5. **Zależności:** endpointy allowlist w Electron, ustawienia `LocalStore`, API KB, Ollama zainstalowane.
6. **Etapy:** (a)–(f) — metody engine, ustawienia loopback/model/opt-in, orchestrator, IPC KB, UI status/uncertainty i testy mock — wdrożone. Import PDF do FTS5 oraz przypisywanie cytatów z odpowiedzi modelu do fragmentów są wdrożone i przetestowane; obrazy nie są OCR-owane. Kontrolowane zapytania regresyjne, ograniczone rozszerzenie prefiksowe polskich tokenów i opcjonalne reranking embeddingami z Ollama są wdrożone. Semantyczny reranking porównuje zapytanie z fragmentami kandydatów lokalnie; awaria wraca do FTS5. Pozostają testy UI, niezależna ocena jakości wyszukiwania/cytowań na reprezentatywnych dokumentach oraz weryfikacja na rzeczywistym modelu lokalnym.
7. **Pliki:** `Sentinel.Engine/Program.cs`, `desktop/electron/main.cjs`, preload typy, `desktop/src/main.tsx`, Core tests.
8. **Prywatność:** dane zostają na loopback; tylko treść podana do analizy; osobne potwierdzenie modelu; redakcja; KB tylko lokalna.
9. **Testy:** mock HTTP test (response/timeout/invalid/schema), provider settings, KB import/delete/limit, tekstowy PDF, limit 500 stron, malformed PDF bez zmiany indeksu, IPC allowlist, brak Ollama i fallback. Testy mock sprawdzają format `/api/embed`, walidację wymiarów wektorów, redakcję sekretów z fragmentów KB i zmianę kolejności kandydatów. `ControlledRetrievalQueriesRankRelevantKnowledgeSourcesInTopThree` buduje 6 dokumentów syntetycznych i sprawdza 4 zapytania; Hit@3=100%, MRR=1,00. Pełny zestaw Release .NET przeszedł 287/287; nie jest to niezależna ocena trafności.
10. **Akceptacja:** UI nie nazywa AI aktywnym bez opt-in; `UseLocalAI=false` domyślnie; mock potwierdza loopback request, nieufny kontekst i fallback; odpowiedź zawiera niepewność, a trafione źródła są nazwane, lecz nie ma cytowania twierdzenie–źródło. Nie używa chmury.
11. **Ryzyka:** lokalny model może halucynować; model może mieć obciążenie/odmowę; FTS5 nie jest semantyczne.
12. **Status:** `IN_PROGRESS` — aktywny klient ma lokalny import TXT/MD/DOCX i tekstowych PDF, listę, wyszukiwanie FTS5 z nazwą źródła i numerem fragmentu oraz usuwanie przez ograniczone IPC. DOCX ekstrakcja jest strumieniowana, respektuje cancellation token, ogranicza wyjście do 2 mln znaków podczas odczytu i odrzuca DTD/encje zewnętrzne; KnowledgeBaseTests 15/15, pełny Release .NET 350/350 bez pominięć. PDF ma limit 10 MB/500 stron/2 mln znaków; import nie wykonuje OCR. Licencja PdfPig 0.1.16 (Apache-2.0 i dodatkowe komponenty) jest dołączana do publikowanego katalogu Engine i do instalatora. UI może sprawdzić modele Ollama pod loopbackiem i jawnie włączyć provider; opcjonalnie można wskazać oddzielny model embeddingowy. Transport HTTP Engine wyłącza proxy i automatyczne przekierowania; test lokalnego serwera potwierdza, że treść `/api/chat` nie jest wysyłana do endpointu przekazanego w odpowiedzi 302. `AnalysisOrchestrator` pobiera do pięciu dopasowanych leksykalnie fragmentów albo do 20 kandydatów FTS5 do rerankingu, a potem przekazuje maksymalnie pięć jako niezaufane źródła. Tekst zapytania i fragmenty KB są redagowane przed wysłaniem do embeddingów; gdy embeddingi zawiodą, system używa kolejności leksykalnej i zgłasza niepewność. Wskaźnik modelu może cytować wybrane indeksy źródeł; backend odrzuca nieistniejące, zduplikowane i poza zakresem indeksy, a UI pokazuje nazwę, numer fragmentu oraz tekst. Cytat jest wskazaniem modelu, nie oceną trafności. Test regresyjny czterech syntetycznych zapytań potwierdza Hit@3=100% i MRR=1,00 w tym kontrolowanym korpusie; nie jest niezależną ani reprezentatywną miarą jakości. Treści nie wchodzą do event history. 2026-10-24 testy `AIProviderTests` na mock HTTP przeszły 15/15; kontrola lokalna nie znalazła polecenia/procesu Ollama ani nasłuchu na `127.0.0.1:11434`, więc rzeczywistego modelu embeddingowego nie zweryfikowano.
13. **Ulepszenie wyszukiwania (2026-10-22):** dla długich tokenów zapytanie FTS5 zachowuje dopasowanie dokładne i dodaje alternatywę prefiksową obciętą o trzy znaki; krótkie słowa pozostają dokładne. Regresja sprawdza „logowania” → „logować” i kontrolowany benchmark zachowuje wyniki. To ograniczona heurystyka morfologiczna, która może rozszerzać wyniki; nie zastępuje lematyzacji ani reprezentatywnej oceny jakości.
