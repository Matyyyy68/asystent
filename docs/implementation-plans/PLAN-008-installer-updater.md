# PLAN-008 — instalator, naprawa i updater

1. **Cel:** cykl install/update/rollback/uninstall bez utraty danych i z weryfikowalnym artefaktem.
2. **Stan obecny:** `installer/Sentinel.Setup` wykonuje staging, per-user, hash payloadu, ACL, log, cancel, preservation plików i self-test. Self-test 0.15.12 ujawnił powtarzalne odrzucenie `chrome_100_percent.pak`; przyczyną był odczyt długości przed opróżnieniem bufora `FileStream`. Dodano `Flush()` przed weryfikacją rozmiaru oraz asercje wskaźnika danych i nagłówków obu baz SQLite po smoke teście. Nowy self-test lokalnego, nieopublikowanego buildu sprawdza aktualizację istniejącego katalogu przez jawny override ścieżki dostępny tylko w trybie testowym: zastąpienie zmienionego `Sentinel.Engine.exe`, zachowanie pliku spoza payloadu oraz rollback po anulowaniu po zamianie katalogów. Faktyczna rejestracja/odczyt HKCU nie jest objęta tym testem. Wynik: `SELF_TEST_SUCCESS payload=true chromiumAcl=true update=true rollback=true appSmoke=true`; po teście katalogi tymczasowe usunięto. Opublikowany v0.15.38 nadal zawiera poprzednią wersję self-testu. Czysty Windows pełny cykl GUI nie został wykonany.
3. **Braki:** dedykowane naprawianie z GUI, podpis cyfrowy, automatyczny updater i rollback wersji; ręczne sprawdzenie skrótów/autostartu/hosta/uninstall.
4. **Decyzje:** nie aktualizować po cichu; podpisany manifest + hash przed update; zachować dane; nie robić self-update z uruchomionego pliku bez atomowego helpera.
5. **Zależności:** certyfikat Authenticode, release workflow, schema version, czysty Windows VM.
6. **Etapy:** (a) czysta instalacja/GUI; (b) update/cancel/rollback; (c) repair; (d) signed CI asset; (e) updater opt-in; (f) uninstall/data checks.
7. **Pliki:** `installer/`, build/release workflows, user validation docs, changelog.
8. **Prywatność:** log lokalny; brak telemetry; nie zmieniać sieci/Defendera.
9. **Testy:** `npm run package` weryfikuje hash payloadu, ekstrakcję, ACL Chromium, uruchomienie renderer → IPC → silnik .NET → SQLite oraz nagłówki obu baz. Lokalny self-test izolowany potwierdza update, zachowanie pliku spoza payloadu, cancel/rollback po swapie, poprawny hash, odrzucenie zmienionego payloadu, preflight niewystarczającego miejsca i zachowanie poprzedniej instalacji po wstrzykniętym błędzie stagingu. Fizyczne zapełnienie woluminu, pełen cykl GUI na clean VM i awaria rejestracji hosta pozostają niewykonane. Windows installer release/self-test `39489181456` PASS dla opublikowanego v0.15.38, ale ten Release nie zawiera jeszcze rozszerzonego testu transakcji.
10. **Akceptacja:** install/update/rollback/uninstall przechodzą na czystym Windows; zachowane dane; signature valid; brak admina jeśli nie wymaga.
11. **Ryzyka:** brak signing certificate blokuje zaufany update; SmartScreen; polityki firmowe.
