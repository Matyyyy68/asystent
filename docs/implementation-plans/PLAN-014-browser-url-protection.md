# PLAN-014 — ochrona URL w rozszerzeniu przeglądarki

1. **Cel:** ostrzegać użytkownika przed URL-em, który bieżące reguły Sentinel rozpoznają jako podejrzany, przy jawnej kontroli integracji i bez przesyłania historii przeglądania.
2. **Stan obecny:** Manifest V3 obsługuje Chrome i Edge przez Native Messaging host. Host produkcyjny korzysta z `UrlRequestProcessor`; analizuje nawigacje głównej karty przed nawigacją, końcowy URL po przekierowaniu (`onCommitted`) i zmiany historii SPA (`onHistoryStateUpdated`), a zgodę `integrationEnabled` odczytuje przed wysłaniem adresu. Zdarzenia dla tego samego URL są deduplikowane; ramki podrzędne są pomijane. Testy jednostkowe sprawdzają przekierowanie, deduplikację, iframe, zamknięcie karty przy oczekującej analizie (bez późniejszego ostrzeżenia) i usuwanie szczegółów ostrzeżenia z session storage, fail-closed, odczyt ustawienia, stan ostrzeżenia po restarcie service workera oraz fail-open przy wyjątku `connectNative` i rozłączeniu hosta. Harness E2E przeszedł na Chrome 155.0.8059.86 i Edge 155.0.4283.62: `status`, `analyze`, produkcyjna reguła `url.brand`, ostrzeżenie z redakcją URL-a/hosta, przekierowanie 302 do podejrzanej domeny, pominięcie iframe, nawigacja SPA `history.pushState` oraz dwa jednoczesne ostrzeżenia niezależnych kart; zamknięcie jednej karty nie zmieniło ostrzeżenia w drugiej. Oba testy użyły osobnych profili i domen `.test`, zablokowały zewnętrzne rozwiązywanie DNS i usunęły własne profile oraz wpisy HKCU.
3. **Braki:** nie zweryfikowano pełnej instalacji/aktualizacji/deinstalacji rozszerzenia i hosta w świeżym profilu Chrome i Edge. Brak hosta i jego rozłączenie są objęte testami jednostkowymi, ale nie E2E w zainstalowanej przeglądarce. Nie ma E2E dla pobierania; krótkie nawigacje i zmiany fragmentu mogą zostać pominięte. Brak jest polityki wydawania i aktualizacji rozszerzenia podpisanej przez zaufanego wydawcę.
4. **Decyzje architektoniczne:** przechowuj zgodę w `chrome.storage.local` i nie kontaktuj się z hostem przed jej odczytem. Ogranicz uprawnienia manifestu do wymaganych hostów i funkcji. Rozszerzenie tylko przedstawia wynik lokalnego hosta; nie wysyła URL-i do zewnętrznego reputacyjnego API i nie blokuje nawigacji bez jawnej decyzji użytkownika.
5. **Zależności:** Manifest V3, `chrome.storage`, Native Messaging, `Sentinel.UrlHost`, `UrlRequestProcessor`, istniejące UI ostrzeżenia oraz Chrome/Edge.
6. **Etapy:** (a) testy jednostkowe i statyczne uprawnień — wdrożone; (b) fail-closed zgody i obsługa restartu service workera — wdrożone; (c) Chrome i Edge E2E z fixture `.test` i produkcyjnym procesorem — wdrożone; (d) SPA, przekierowanie HTTP 302, deduplikacja i pominięcie iframe w testach jednostkowych oraz E2E Chrome/Edge — wdrożone; (e) czyszczenie stanu po zamknięciu karty i ignorowanie spóźnionej odpowiedzi — test jednostkowy oraz Chrome/Edge E2E z dwiema kartami wdrożone; (f) pełny test instalacji hosta i rozszerzenia oraz E2E pobierania — otwarte; (g) aktualizacja i deinstalacja w czystych profilach oraz kontrola braku pozostałości — otwarte.
7. **Pliki:** `browser-extension/manifest.json`, `browser-extension/service-worker.js`, `browser-extension/content-script.js`, `browser-extension/warning.html`, `browser-extension/warning.js`, `tests/Sentinel.NativeMessagingEngineHost`, `scripts/test-chrome-extension-e2e.cjs`, `installer/Sentinel.Setup/Program.cs`.
8. **Prywatność:** integracja jest opt-in; URL trafia wyłącznie do lokalnego Native Messaging hosta. Błędy i UI nie ujawniają surowego URL-a ani hosta w historii diagnostycznej. E2E używa wyłącznie domeny `.test`, blokuje zewnętrzne DNS i sprząta profil oraz rejestrację hosta.
9. **Testy:** desktop testy Node 21/21, w tym końcowy URL po przekierowaniu analizowany raz, duplikat `onCommitted` i iframe pominięte, SPA analizowane raz, zamknięcie karty ignorujące spóźnioną odpowiedź i czyszczące session storage, fail-closed przy wyłączonej/niedostępnej zgodzie i fail-open przy braku/rozłączeniu hosta; walidator manifestu, host .NET bez ostrzeżeń i test `UrlRequestProcessor`. E2E `node scripts/test-chrome-extension-e2e.cjs chrome` oraz `node scripts/test-chrome-extension-e2e.cjs edge` PASS dla `status`/`analyze`, ostrzeżenia z redakcją URL-a/hosta, przekierowania HTTP 302, pominięcia iframe, trasy SPA `history.pushState` oraz dwóch ostrzeganych kart, z których zamknięcie jednej nie wpływa na drugą; po obu przebiegach sprawdzono usunięcie profilu i wpisu HKCU. E2E pobierania pozostaje otwarte.
10. **Kryteria akceptacji:** zgoda wyłączona lub niedostępna nigdy nie wysyła URL-a; alert pokazuje wyłącznie zredagowane szczegóły; niepoprawny/brakujący host nie blokuje przeglądarki; Chrome i Edge przechodzą instalację, update i uninstall na czystych profilach bez pozostałości; wszystkie hosty i pliki manifestu mają weryfikowalny hash.
11. **Ryzyka i ograniczenia:** URL może zawierać dane wrażliwe, dlatego nie należy go logować ani przesyłać zewnętrznie. Silnik lokalny nadal ma krytyczne ograniczenia detekcji F03. Harmonogram zdarzeń Chrome może pominąć bardzo krótką nawigację; ten plan nie stanowi gwarancji blokowania każdej strony phishingowej.
