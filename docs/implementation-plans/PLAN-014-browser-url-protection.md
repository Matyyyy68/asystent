**F09 — headless E2E w odizolowanym Windows CI (2026-10-25, weryfikacja oczekuje na run):** harness ma jawny `--allow-headless-browser`; workflow uruchamia Chrome i Edge na runnerze GitHub Actions, w osobnym profilu i z Native Messaging hostem używającym produkcyjnego `UrlRequestProcessor`. Nie uruchamiano lokalnej przeglądarki. Lokalne kontrole składni, opt-in guard, desktop 47/47, diff i plany 14/14 PASS; dopiero CI rozstrzygnie, czy headless Chrome/Edge obsługuje wymagane API rozszerzeń.

**F09 — regresja akcji pobierania (2026-10-24):** handler background odrzuca `continue` dla ważnego ostrzeżenia `kind=download`, nawet jeśli UI jeszcze nie ukryło przycisku. Zapobiega ponownej nawigacji do źródła i rozpoczęciu drugiego pobrania; zachowuje token ostrzeżenia, więc użytkownik nadal może zamknąć kartę albo jawnie zatrzymać pierwotny transfer. Test Node potwierdza odmowę i brak aktualizacji karty. Pełny desktop `npm test` 37/37 PASS; bez startu przeglądarki.

1. **Cel:** ostrzegać użytkownika przed URL-em, który bieżące reguły Sentinel rozpoznają jako podejrzany, przy jawnej kontroli integracji i bez przesyłania historii przeglądania.
2. **Stan obecny:** Manifest V3 obsługuje Chrome i Edge przez Native Messaging host oraz uprawnienie `downloads`. Po opt-in `integrationEnabled` zdarzenie `downloads.onCreated` analizuje końcowy URL pobrania (bez nazwy pliku, lokalnej ścieżki i referrera) i przy podejrzanym wyniku otwiera osobną kartę ostrzegawczą. Ostrzeżenie zawiera opcjonalny przycisk zatrzymania konkretnego transferu; jego użycie wymaga kliknięcia użytkownika i nie usuwa pliku, który zdążył się pobrać. Rozszerzenie nie analizuje treści pliku. Host produkcyjny korzysta z `UrlRequestProcessor`; analizuje nawigacje głównej karty przed nawigacją, końcowy URL po przekierowaniu (`onCommitted`) i zmiany historii SPA (`onHistoryStateUpdated`), a zgodę `integrationEnabled` odczytuje przed wysłaniem adresu. Zdarzenia dla tego samego URL są deduplikowane; ramki podrzędne są pomijane. Testy jednostkowe sprawdzają przekierowanie, deduplikację, iframe, zamknięcie karty przy oczekującej analizie (bez późniejszego ostrzeżenia) i usuwanie szczegółów ostrzeżenia z session storage, fail-closed, odczyt ustawienia, stan ostrzeżenia po restarcie service workera, zatrzymanie tylko ID transferu przypisanego do ważnego ostrzeżenia oraz fail-open przy wyjątku `connectNative` i rozłączeniu hosta. Harness E2E przeszedł na Chrome 155.0.8059.86 i Edge 155.0.4283.62: `status`, `analyze`, produkcyjna reguła `url.brand`, ostrzeżenie z redakcją URL-a/hosta, przekierowanie 302 do podejrzanej domeny, pominięcie iframe, nawigacja SPA `history.pushState`, dwa jednoczesne ostrzeżenia niezależnych kart oraz nawigacja do odpowiedzi pobieranej z podejrzanej domeny; zamknięcie jednej karty nie zmieniło ostrzeżenia w drugiej. Test pobierania potwierdza analizę adresu i zapis fixture wyłącznie w profilu tymczasowym, nie analizę pobranej zawartości. Testy użyły osobnych profili i domen `.test`, zablokowały zewnętrzne rozwiązywanie DNS i usunęły własne profile oraz wpisy HKCU.
3. **Braki:** nie zweryfikowano pełnej instalacji/aktualizacji/deinstalacji rozszerzenia i hosta w świeżym profilu Chrome i Edge. Brak hosta i jego rozłączenie są objęte testami jednostkowymi, ale nie E2E w zainstalowanej przeglądarce. Linkowe pobrania mają teraz testy jednostkowe oraz Chrome/Edge E2E na runnerze Windows CI; E2E używa kontrolowanego fixture w profilu tymczasowym, więc nie dowodzi pełnej instalacji ani testu zwykłego profilu użytkownika. Przycisk zatrzymania nie gwarantuje przerwania zakończonego transferu, a pobrane bajty nie są analizowane przez rozszerzenie. Krótkie nawigacje i zmiany fragmentu mogą zostać pominięte. Brak jest polityki wydawania i aktualizacji rozszerzenia podpisanej przez zaufanego wydawcę.
4. **Decyzje architektoniczne:** przechowuj zgodę w `chrome.storage.local` i nie kontaktuj się z hostem przed jej odczytem. Ogranicz uprawnienia manifestu do wymaganych hostów i funkcji; `downloads` służy do wykrywania rozpoczęcia transferu oraz jawnego zatrzymania transferu wskazanego przez ostrzeżenie. Rozszerzenie tylko przedstawia wynik lokalnego hosta; nie wysyła URL-i do zewnętrznego reputacyjnego API i nie blokuje nawigacji bez jawnej decyzji użytkownika.
