# PLAN-007 — baza danych i prywatność

1. **Cel:** odporna lokalna baza z jasną retencją, backup/restore i kontrolą dostępu.
2. **Stan obecny:** SQLite historii/ustawień jest po migracji v6, historia ma retencję i limit odczytu 500 zdarzeń. UI/IPC eksportuje redagowany JSON, tworzy kopie obu baz i przywraca obie bazy po walidacji integralności/schematu/metadanych. Restore historii zachowuje profil instalacji; restore wiedzy odtwarza dokumenty i FTS5. UI jawnie informuje o braku szyfrowania. Testy sprawdzają round-trip, wyszukiwanie po restore i odrzucenie uszkodzonych kopii bez utraty aktywnych danych.
3. **Braki:** limit 512 MiB ogranicza plik głównej bazy historii; test pojemności wymusza `SQLITE_FULL`, potwierdza rollback i zachowanie rekordów. Test monitorowania procesu dochodzi do odmowy zapisu małymi zdarzeniami i potwierdza retry po zwolnieniu miejsca. ACL testuje odmowę tworzenia plików w katalogu użytkownika i bezpieczne niepowodzenie inicjalizacji; nie weryfikuje polityki ACL używanej przez zainstalowany produkt. Brak fizycznego testu no-space na oddzielnym wolumenie i długotrwałego testu obciążeniowego. Baza wiedzy ogranicza indeks do 100 dokumentów i 20 mln znaków. UI/status pokazuje rozmiar DB/WAL/SHM, page count/freelist i rekordy obu baz; 32 równoległe zapisy przechodzą bez utraty rekordów. Uszkodzone SQLite jest testowane, ale inne rodzaje awarii jeszcze nie.
4. **Decyzje:** ACL per-user; nie obiecywać szyfrowania przy braku klucza; export redaguje dane; backup atomowy i wersjonowany.
5. **Zależności:** wspólny schema, Windows ACL, decyzje retencji.
6. **Etapy:** (a) model threat/data inventory; (b) diagnostyka obu baz, limity importu wiedzy i 512 MiB limit historii wdrożone; (c) backup obu baz i kontrola możliwości otwarcia kopii; (d) UI export/delete/backup/restore i komunikat o zapełnieniu; (e) symulowany disk full, retry monitorów, ACL fail-closed i współbieżność PASS; fizyczny wolumen oraz długotrwałe obciążenie do sprawdzenia.
7. **Pliki:** `LocalStore.cs`, testy, Engine, UI, privacy docs.
8. **Prywatność:** baza nieszyfrowana w spoczynku; minimalizować, redagować logi, jawnie pokazać gdzie leży.
9. **Testy:** eksport bez pełnej treści/URL, kopia obu SQLite, restore dokumentów i wyszukiwania FTS5, restore historii/settings z zachowaniem profilu, odrzucenie corrupt bez zmiany aktywnych danych, retencja, 32 równoległe zapisy, pomiar storage, symulowany `SQLITE_FULL`, retry obserwatora i Windows ACL odmowy tworzenia plików — PASS. Test ACL przywraca odziedziczone uprawnienia w `finally`. Fizyczny brak miejsca na odrębnym wolumenie, ACL zainstalowanej lokalizacji danych i długotrwałe obciążenie pozostają niewykonane.
10. **Akceptacja:** kopie przechodzą `integrity_check`; restore obsługiwanych wersji waliduje dane przed transakcją; błędna kopia nie modyfikuje aktywnej bazy; profil instalacji pozostaje bez zmian; eksport nie zawiera surowej treści/URL.
11. **Ryzyka:** SQLite file encryption wymaga osobnej zależności/klucza i może utrudnić naprawę.
12. **Status:** `IN_PROGRESS` — eksport, backup/restore obu baz, pomiar rozmiaru, limity bazy wiedzy, limit 512 MiB historii, symulowany `SQLITE_FULL`, retry monitorów, test współbieżności i Windows ACL fail-closed wdrożone i testowane; pełny zestaw .NET 163/163 PASS (2026-10-20). Pozostają test fizycznego braku miejsca na odrębnym wolumenie, ACL polityki zainstalowanej lokalizacji danych i długotrwałe obciążenie.
