# PLAN-007 — baza danych i prywatność

1. **Cel:** odporna lokalna baza z jasną retencją, backup/restore i kontrolą dostępu.
2. **Stan obecny:** SQLite historii/ustawień jest po migracji v6, historia ma retencję i limit odczytu 500 zdarzeń. UI/IPC eksportuje redagowany JSON, tworzy kopie obu baz i przywraca obie bazy po walidacji integralności/schematu/metadanych. Restore historii zachowuje profil instalacji; restore wiedzy odtwarza dokumenty i FTS5. UI jawnie informuje o braku szyfrowania. Testy sprawdzają round-trip, wyszukiwanie po restore i odrzucenie uszkodzonych kopii bez utraty aktywnych danych.
3. **Braki:** limit 512 MiB ogranicza plik głównej bazy historii; rozszerzony test pojemności wymusza `SQLITE_FULL`, potwierdza rollback transakcji i zachowanie istniejących rekordów. Brak fizycznego testu no-space na oddzielnym wolumenie oraz sprawdzenia ACL ścieżek. Baza wiedzy ogranicza indeks do 100 dokumentów i 20 mln znaków, odrzucając nadmiar bez usuwania istniejących danych. UI/status pokazuje rozmiar DB/WAL/SHM, page count/freelist i rekordy obu baz; 32 równoległe zdarzenia zapisu przechodzą test bez utraty rekordów. Test obciążeniowy i ACL nadal wymagają wykonania. Uszkodzone SQLite jest testowane, ale inne rodzaje awarii jeszcze nie.
4. **Decyzje:** ACL per-user; nie obiecywać szyfrowania przy braku klucza; export redaguje dane; backup atomowy i wersjonowany.
5. **Zależności:** wspólny schema, Windows ACL, decyzje retencji.
6. **Etapy:** (a) model threat/data inventory; (b) diagnostyka obu baz, limity importu wiedzy i 512 MiB limit historii wdrożone; (c) backup obu baz i kontrola możliwości otwarcia kopii; (d) UI export/delete/backup/restore i komunikat o zapełnieniu; (e) testy symulowanego disk full/concurrency PASS; fizyczny wolumen i ACL do sprawdzenia.
7. **Pliki:** `LocalStore.cs`, testy, Engine, UI, privacy docs.
8. **Prywatność:** baza nieszyfrowana w spoczynku; minimalizować, redagować logi, jawnie pokazać gdzie leży.
9. **Testy:** eksport bez pełnej treści/URL, kopia obu SQLite, restore dokumentów i wyszukiwania FTS5, restore historii/settings z zachowaniem profilu, odrzucenie corrupt bez zmiany aktywnych danych, retencja, 32 równoległe zapisy, pomiar storage i symulowany `SQLITE_FULL` PASS; test pełnej bazy potwierdza odrzucenie zapisu bez utraty wcześniejszych wpisów. Fizyczny brak miejsca na odrębnym wolumenie i ACL check pozostają niewykonane.
10. **Akceptacja:** kopie przechodzą `integrity_check`; restore obsługiwanych wersji waliduje dane przed transakcją; błędna kopia nie modyfikuje aktywnej bazy; profil instalacji pozostaje bez zmian; eksport nie zawiera surowej treści/URL.
11. **Ryzyka:** SQLite file encryption wymaga osobnej zależności/klucza i może utrudnić naprawę.
12. **Status:** `IN_PROGRESS` — eksport, backup/restore obu baz, pomiar rozmiaru, limity bazy wiedzy, limit 512 MiB historii i symulowany test `SQLITE_FULL` wdrożone i testowane; testy limitu liczby dokumentów/20 mln znaków, współbieżności i zachowania istniejących danych przy zapełnieniu PASS. Fizyczny brak miejsca, obciążenie długotrwałe i ACL pozostają.
