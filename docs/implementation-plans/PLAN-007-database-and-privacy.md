# PLAN-007 — baza danych i prywatność

1. **Cel:** odporna lokalna baza z jasną retencją, backup/restore i kontrolą dostępu.
2. **Stan obecny:** bieżąca gałąź ma SQLite v14; v13 dodaje ulotne grupy korelacji domeny przechowywane jako hash i czyszczone przy restore, a v14 trwale oznacza obcięty snapshot procesów. Historia ma retencję i limit odczytu 500 zdarzeń. UI/IPC eksportuje redagowany JSON i CSV, pakiet diagnostyczny bez historii i identyfikujących ścieżek, tworzy kopie obu baz i przywraca bazę historii/ustawień z wersji v6–v14 po walidacji integralności/schematu/metadanych. Migracja kolejki Enterprise v9→v10 zachowuje wpisy, a starsze rekordy oznacza `unknown`/null/1; kolejne migracje dodają correlationId i walidowane evidence codes bez utraty historii. Eksport CSV ma UTF-8 BOM, quoting i ochronę przed formułami arkusza. Restore historii zachowuje profil instalacji i bieżące baseline'y monitorów; restore wiedzy odtwarza dokumenty i FTS5. Baseline procesu zapisuje tylko aplikacje niewykluczone. UI jawnie informuje o braku szyfrowania. Testy sprawdzają round-trip, wyszukiwanie po restore, atomowość baseline'ów, prywatność eksportów i odrzucenie uszkodzonych kopii bez utraty aktywnych danych.
3. **Braki:** limit 512 MiB ogranicza plik głównej bazy historii; test pojemności wymusza `SQLITE_FULL`, potwierdza rollback i zachowanie rekordów. Test monitorowania procesu dochodzi do odmowy zapisu małymi zdarzeniami i potwierdza retry po zwolnieniu miejsca. Windows self-test instaluje payload w unikalnym katalogu pod `%LOCALAPPDATA%\Programs`, uruchamia aplikację z odizolowanym katalogiem danych pod `%LOCALAPPDATA%`, a następnie sprawdza utworzenie obu baz SQLite — zapis w tych lokalizacjach przeszedł. Nie sprawdza domyślnej lokalizacji bieżącej instalacji użytkownika. Brak fizycznego testu no-space na oddzielnym wolumenie i długotrwałego testu obciążeniowego. Baza wiedzy ogranicza indeks do 100 dokumentów i 20 mln znaków. UI/status pokazuje rozmiar DB/WAL/SHM, page count/freelist i rekordy obu baz; 32 równoległe zapisy przechodzą bez utraty rekordów. Uszkodzone SQLite jest testowane, ale inne rodzaje awarii jeszcze nie.
4. **Decyzje:** ACL per-user; nie obiecywać szyfrowania przy braku klucza; export redaguje dane; backup atomowy i wersjonowany.
5. **Zależności:** wspólny schema, Windows ACL, decyzje retencji.
6. **Etapy:** (a) model threat/data inventory; (b) diagnostyka obu baz, limity importu wiedzy i 512 MiB limit historii wdrożone; (c) backup obu baz i kontrola możliwości otwarcia kopii; (d) UI export/delete/backup/restore i komunikat o zapełnieniu; (e) symulowany disk full, retry monitorów, ACL fail-closed i współbieżność PASS; fizyczny wolumen oraz długotrwałe obciążenie do sprawdzenia.
7. **Pliki:** `LocalStore.cs`, testy, Engine, UI, privacy docs.
8. **Prywatność:** baza nieszyfrowana w spoczynku; minimalizować, redagować logi, jawnie pokazać gdzie leży.
9. **Testy:** eksport bez pełnej treści/URL, kopia obu SQLite, restore dokumentów i wyszukiwania FTS5, restore historii/settings z zachowaniem profilu, odrzucenie corrupt bez zmiany aktywnych danych, retencja, 32 równoległe zapisy, pomiar storage, symulowany `SQLITE_FULL`, retry obserwatora i Windows ACL odmowy tworzenia plików — PASS. Test ACL przywraca odziedziczone uprawnienia w `finally`. Rozszerzony lokalny Windows installer self-test z rzeczywistymi katalogami nadrzędnymi pod `%LOCALAPPDATA%` oraz inicjalizacją obu baz PASS; katalogi testowe zostały usunięte. Fizyczny brak miejsca na odrębnym wolumenie, domyślna ścieżka aktywnej instalacji i długotrwałe obciążenie pozostają niewykonane.
10. **Akceptacja:** kopie przechodzą `integrity_check`; restore obsługiwanych wersji waliduje dane przed transakcją; błędna kopia nie modyfikuje aktywnej bazy; profil instalacji pozostaje bez zmian; eksport nie zawiera surowej treści/URL.
11. **Ryzyka:** SQLite file encryption wymaga osobnej zależności/klucza i może utrudnić naprawę.
12. **Status:** `IN_PROGRESS` — eksport, backup/restore obu baz, pomiar rozmiaru, limity bazy wiedzy, limit 512 MiB historii i SQLite v14 wdrożone. Restore v6–v14, atomowe zmiany baseline'ów/zdarzeń, symulowany `SQLITE_FULL`, retry monitorów, współbieżność i Windows ACL fail-closed wdrożone/testowane. Bieżąca lokalna walidacja Windows: .NET 211/211 bez pominięć, pełny `scripts/build-user.ps1 -Installer`, testy serwera 22/22 PASS. Nie dowodzi to testu fizycznego braku miejsca ani długiego obciążenia. Self-test instalatora używa izolowanych katalogów pod `%LOCALAPPDATA%`, nie zastępuje ACL domyślnej lokalizacji bieżącej instalacji. Pozostają fizyczny brak miejsca na odrębnym wolumenie, test ACL po rzeczywistej instalacji i długotrwałe obciążenie.
