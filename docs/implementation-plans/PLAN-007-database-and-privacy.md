# PLAN-007 — baza danych i prywatność

1. **Cel:** odporna lokalna baza z jasną retencją, backup/restore i kontrolą dostępu.
2. **Stan obecny:** bieżąca gałąź używa SQLite v34, a restore obsługuje kopie v6–v34. Migracje v13–v26 dodały m.in. korelację domen, limity snapshotów, obserwacje scalonych sygnałów, kolejkę Enterprise, metadane inspekcji procesów, baseline'y Run/Scheduled Tasks, DNS Operational, czas przetworzenia, kody ograniczeń, usługi i sterowniki oraz stan cichego baseline'u usług. Migracje v27–v34 rozszerzyły monitorowanie polityk/Winlogon, AppInit DLLs, IFEO Debugger, ShellServiceObjectDelayLoad, RunOnceEx, SilentProcessExit i StartupApproved; zakres źródeł opisuje macierz F21. Historia ma retencję i limit odczytu 500 zdarzeń. UI/IPC eksportuje redagowany JSON i CSV, pakiet diagnostyczny bez historii i identyfikujących ścieżek oraz kopie obu baz po walidacji integralności/schematu/metadanych. Eksport CSV ma UTF-8 BOM, quoting i ochronę przed formułami arkusza. Restore historii zachowuje profil instalacji i bieżące baseline'y monitorów; restore wiedzy odtwarza dokumenty i FTS5. Baseline procesu zapisuje tylko aplikacje niewykluczone. UI jawnie informuje o braku szyfrowania. Testy sprawdzają round-trip, wyszukiwanie po restore, atomowość baseline'ów, prywatność eksportów i odrzucenie uszkodzonych kopii bez utraty aktywnych danych.
**Walidacja wskaźnika danych:** wspólny helper `DataDirectoryPointer` ogranicza odczyt `data-path.txt` do 4 KiB poprawnego UTF-8 i odrzuca ścieżki względne, UNC oraz katalog główny dysku. Engine nie przełącza się po cichu na nową bazę przy uszkodzonym/niedostępnym pliku; URL host pomija dostęp do lokalnego feedu i historii. .NET testy sprawdzają rozmiar, kodowanie, blokadę pliku i lokalność; Engine IPC/DNS/TCP/UDP przechodzi. To nie zastępuje weryfikacji ACL rzeczywistej ścieżki po instalacji.
3. **Braki:** limit 512 MiB ogranicza plik głównej bazy historii; test pojemności wymusza `SQLITE_FULL`, potwierdza rollback i zachowanie rekordów. Test monitorowania procesu dochodzi do odmowy zapisu małymi zdarzeniami i potwierdza retry po zwolnieniu miejsca. Windows self-test instaluje payload w unikalnym katalogu pod `%LOCALAPPDATA%\Programs`, uruchamia aplikację z odizolowanym katalogiem danych pod `%LOCALAPPDATA%`, a następnie sprawdza utworzenie obu baz SQLite — zapis w tych lokalizacjach przeszedł. Nie sprawdza domyślnej lokalizacji bieżącej instalacji użytkownika. Brak fizycznego testu no-space na oddzielnym wolumenie i długotrwałego testu obciążeniowego. Baza wiedzy ogranicza indeks do 100 dokumentów i 20 mln znaków. UI/status pokazuje rozmiar DB/WAL/SHM, page count/freelist i rekordy obu baz; 32 równoległe zapisy przechodzą bez utraty rekordów. Uszkodzone SQLite jest testowane, ale inne rodzaje awarii jeszcze nie.
4. **Decyzje:** ACL per-user; nie obiecywać szyfrowania przy braku klucza; export redaguje dane; backup atomowy i wersjonowany.
5. **Zależności:** wspólny schema, Windows ACL, decyzje retencji.
6. **Etapy:** (a) model threat/data inventory; (b) diagnostyka obu baz, limity importu wiedzy i 512 MiB limit historii wdrożone; (c) backup obu baz i kontrola możliwości otwarcia kopii; (d) UI export/delete/backup/restore i komunikat o zapełnieniu; (e) symulowany disk full, retry monitorów, ACL fail-closed i współbieżność PASS; migracje monitorów do v34 wdrożone; fizyczny wolumen oraz długotrwałe obciążenie do sprawdzenia.
7. **Pliki:** `LocalStore.cs`, testy, Engine, UI, privacy docs.
8. **Prywatność:** baza nieszyfrowana w spoczynku; minimalizować, redagować logi, jawnie pokazać gdzie leży.
9. **Testy:** eksport bez pełnej treści/URL, kopia obu SQLite, restore dokumentów i wyszukiwania FTS5, restore historii/settings z zachowaniem profilu (w tym deferred Enterprise metadata w SQLite v17), odrzucenie corrupt bez zmiany aktywnych danych, retencja, 32 równoległe zapisy, pomiar storage, symulowany `SQLITE_FULL`, retry obserwatora i Windows ACL odmowy tworzenia plików — PASS. Test ACL przywraca odziedziczone uprawnienia w `finally`. Rozszerzony lokalny Windows installer self-test z rzeczywistymi katalogami nadrzędnymi pod `%LOCALAPPDATA%` oraz inicjalizacją obu baz PASS; katalogi testowe zostały usunięte. Fizyczny brak miejsca na odrębnym wolumenie, domyślna ścieżka aktywnej instalacji i długotrwałe obciążenie pozostają niewykonane.
10. **Akceptacja:** kopie przechodzą `integrity_check`; restore obsługiwanych wersji waliduje dane przed transakcją; błędna kopia nie modyfikuje aktywnej bazy; profil instalacji pozostaje bez zmian; eksport nie zawiera surowej treści/URL.
11. **Ryzyka:** SQLite file encryption wymaga osobnej zależności/klucza i może utrudnić naprawę.
12. **Status:** `IN_PROGRESS` — eksport, backup/restore obu baz, pomiar rozmiaru, limity bazy wiedzy, limit 512 MiB historii i SQLite v34 wdrożone. Restore v6–v34 zachowuje baseline'y, a test prywatności potwierdza, że ścieżki/hash nie są w eksporcie JSON. Atomowe zmiany baseline'ów/zdarzeń, symulowany `SQLITE_FULL`, retry monitorów, współbieżność i Windows ACL fail-closed wdrożone/testowane. Migracje v27–v34 dla monitorów Windows są pokryte testami; pełna bramka bieżącego drzewa 2026-10-24 PASS: .NET 350/350 bez pominięć, ewaluatory i plany 13/13, Engine/UrlHost IPC/DNS/TCP/UDP, Electron 16/16, `npm audit` 0, produkcyjny build UI i installer self-test. Odczytowy audyt zależności NuGet 2026-10-24 nie wykrył podatnych pakietów. Nie dowodzi to fizycznego braku miejsca ani długiego obciążenia. Self-test instalatora używa izolowanych katalogów pod `%LOCALAPPDATA%`, nie zastępuje ACL domyślnej lokalizacji bieżącej instalacji. Pozostają fizyczny brak miejsca na odrębnym wolumenie, test ACL po rzeczywistej instalacji i długotrwałe obciążenie.


16. **Czas przetworzenia zdarzeń (SQLite v23):** `events` i `event_observations` zapisują processed_at; nowe zapisy dostają czas UTC, a starsze wpisy zachowują NULL. JSON i CSV eksportują pole, a restore kopii v23 je zachowuje; kopie v6–v22 pozostają wspierane.

17. **Ograniczenia analizy (SQLite v24):** historia przechowuje wyłącznie allowlistowane kody tego, czego nie zweryfikowano. Swobodny tekst niepewności modelu i nazwy źródeł wiedzy nie trafiają do historii; zdarzenia ręcznej analizy pokazują kody po polsku w UI, eksporcie i kopiach. Legacy pozostaje NULL.
