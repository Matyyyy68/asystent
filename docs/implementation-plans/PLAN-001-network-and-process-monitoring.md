# PLAN-001 — monitoring sieci i procesów

1. **Cel:** dostarczać udokumentowane, ograniczone metadane połączeń i zdarzeń procesów, bez przechwytywania treści TLS ani blokowania.
2. **Stan obecny:** Engine pobiera natywne tabele IP Helper do 800 TCP połączeń i 200 lokalnych UDP endpointów, z PID/nazwą procesu gdy dostępne. Domyślnie wyłączony opt-in monitoring co 10 s porównuje baseline i lokalnie zapisuje do 100 nowych zewnętrznych `Established`/`SynSent` TCP oraz nowych lokalnych endpointów UDP jako metadane informacyjne. Endpoint UDP nie dowodzi wysłania datagramu ani nie ujawnia celu zdalnego. SQLite v7 przechowuje sieciowy baseline; SQLite v8 przechowuje baseline procesów. Oba są aktualizowane atomowo ze zdarzeniami. Restart nie powtarza alertów, a wznowienie procesów wykrywa różnice od ostatniej próbki. Pauza procesu przesuwa baseline bez alertów; wykluczone aplikacje nie są trwale zapisywane. Pauza/wyłączenie monitoringu sieci unieważnia baseline przed kolejnym opt-in. Procesy są próbkowane co 5 s i zapisują start/stop do 100 zmian.
3. **Braki:** krótkie połączenia/datagramy/procesy między próbkami, gwarantowany event stream, ścieżka/podpis, reputacja i długotrwała korelacja połączeń z procesami. Pięciominutowy soak z opt-in TCP przeszedł w pojedynczej sesji, ale nie jest długotrwałą gwarancją. Jest tylko korelacja czasowa: TCP event dopisuje fakt zapisania startu tego samego PID w ostatnich 60 s; korelacja resetuje się przy restarcie silnika i nie jest sygnałem zagrożenia. Przy `SQLITE_FULL` transakcja zachowuje poprzedni zatwierdzony baseline, a żywy proces ponawia zdarzenie po odzyskaniu miejsca. Zmiany procesów pomiędzy próbkami i krótkie procesy nadal mogą zostać pominięte. WMI `Win32_ProcessStartTrace` zwróciło `Access denied` dla bieżącego konta.
4. **Decyzje:** zastosowano polling bez podnoszenia uprawnień jako jawny fallback. Event-driven ETW/WMI wymaga osobnej oceny dostępu, kompatybilności i skutków elevated service. Nie używać TLS MITM/WFP ani nie podnosić uprawnień domyślnie.
5. **Zależności:** wspólny `SecurityEvent`, ograniczona kolejka, Windows 10/11 x64, testy w Windows; uprawnienia ETW do potwierdzenia.
6. **Etapy:** (a) prototyp kolektora i benchmark; (b) test mapowania PID na proces; (c) deduplikacja/limity; (d) polityka pause/retencji; (e) test utraty źródła i restartu.
7. **Pliki:** `src/Sentinel.Engine/`, nowe `src/Sentinel.Core/Monitoring/`, testy `tests/Sentinel.Tests/`, IPC `desktop/electron/main.cjs`, UI `desktop/src/main.tsx`.
8. **Prywatność:** wyłącznie IP/port/czas/PID/nazwa pliku w minimalnym zakresie; nie przechowywać payloadów/URL; lokalna retencja i jawny opt-in.
9. **Testy:** Windows IP Helper test sprawdza PID żywego TCP listenera i UDP endpointu. Test jednostkowy kolektora weryfikuje zapis nowego lokalnego UDP endpointu oraz zastrzeżenie, że nie dowodzi datagramu. IPC test potomka weryfikuje zdarzenie start/stop. Integracyjny test wstrzykuje 10 500 PID; kolektor ogranicza próbkę do 10 000 PID, zapis do 100 zdarzeń i poprawnie raportuje pominięcia. Osobny test wymusza awarię źródła i weryfikuje odzyskanie. Test live tworzy kontrolowany listener na interfejsie nie-loopback i potwierdza zapis nowego połączenia po baseline. Test korelacji jest informacyjny. Profil TCP `scripts/benchmark-engine.cjs --duration=300 --tcp-monitor` zebrał 60 próbek co 5 s: CPU silnika 0,056% łącznej mocy logicznych procesorów, working set 45,2 MiB na starcie / 57 MiB maksimum, `collect` mediana 5,6 ms / max 675,9 ms; observer pozostał aktywny, kontrolowane połączenie i 13 zdarzeń TCP zapisano bez pominiętych zmian. To pojedyncza sesja lokalna, nie gwarancja długotrwała ani pomiar pod sztucznym obciążeniem.
10. **Akceptacja:** snapshot pokazuje protokół/adresy/PID/nazwę gdy można; próbkowanie procesów tworzy informacyjne start/stop z PID, respektuje pause/wykluczenia, ogranicza snapshot do 10 000 PID i zapis do 100 zmian oraz raportuje liczbę pominiętych; UI ujawnia ograniczenia; brak blokowania. Krótkie procesy mogą zostać pominięte.
11. **Ryzyka:** snapshoty mogą pominąć połączenia krótkie; ETW zależy od wersji i uprawnień; VPN/TLS ograniczają widoczność.
12. **Status:** `IN_PROGRESS` — natywny snapshot TCP/UDP, trwałe baseline'y SQLite v7/v8, atomowe zapisy baseline'u i zdarzeń, pauza bez alertów procesowych, ograniczona korelacja czasowa PID, limity, retry po `SQLITE_FULL`, testy awarii/restartu i pięciominutowy soak przechodzą lokalne testy. Monitoring sieci jest domyślnie wyłączony; krótkie zdarzenia mogą zostać pominięte, a endpoint UDP nie dowodzi transferu. WMI event stream blokuje brak uprawnień bieżącego konta. Pozostają gwarantowany event stream, pełna korelacja i obsługa krótkich zdarzeń.
