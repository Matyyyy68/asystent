# PLAN-001 — monitoring sieci i procesów

1. **Cel:** dostarczać udokumentowane, ograniczone metadane połączeń i zdarzeń procesów, bez przechwytywania treści TLS ani blokowania.
2. **Stan obecny:** Engine pobiera natywne tabele IP Helper do 800 TCP połączeń i 200 lokalnych UDP endpointów, z PID/nazwą procesu gdy dostępne. Domyślnie wyłączony opt-in monitoring co 10 s porównuje baseline i lokalnie zapisuje do 100 nowych zewnętrznych `Established`/`SynSent` TCP oraz nowych lokalnych endpointów UDP jako metadane informacyjne. Endpoint UDP nie dowodzi wysłania datagramu ani nie ujawnia celu zdalnego. SQLite v7 przechowuje sieciowy baseline; SQLite v8 przechowuje baseline procesów; v14 przechowuje flagę obcięcia snapshotu procesów, a v15 flagi obcięcia tabel TCP/UDP. Oba baseline'y są aktualizowane atomowo ze zdarzeniami. Restart nie powtarza alertów, a wznowienie procesów wykrywa różnice od ostatniej próbki. Pauza procesu przesuwa baseline bez alertów; wykluczone aplikacje nie są trwale zapisywane. Pauza/wyłączenie monitoringu sieci unieważnia baseline przed kolejnym opt-in. Procesy są próbkowane co 5 s, sortowane po PID, ograniczone do 10 000; obcięta próbka nie generuje niepewnych zdarzeń startu/zniknięcia. Próbki sieci są sortowane deterministycznie; przy obcięciu monitor wstrzymuje alerty do kolejnej pełnej próbki i sygnalizuje ten stan.
3. **Braki:** krótkie połączenia/datagramy/procesy między próbkami, gwarantowany event stream, ścieżka/podpis i reputacja. Kandydat v0.15.34 trwale zapisuje correlationId dla startu procesu i połączenia/endpointu z tego samego PID oraz nazwą w oknie 60 s; ID jest tylko korelacją czasową. Mapa aktywnych startów resetuje się przy restarcie silnika i jest czyszczona po pauzie. Przy `SQLITE_FULL` transakcja zachowuje poprzedni zatwierdzony baseline, a żywy proces ponawia zdarzenie po odzyskaniu miejsca. Zmiany procesów pomiędzy próbkami i krótkie procesy nadal mogą zostać pominięte. WMI `Win32_ProcessStartTrace` zwróciło `Access denied`. Próba `logman create trace` dla providera `Microsoft-Windows-Kernel-Process` również zwróciła `Access denied`, mimo członkostwa bieżącego konta w `Performance Log Users`; nie uruchomiono sesji ETW ani nie zmieniono polityk systemowych.
4. **Decyzje:** zastosowano polling bez podnoszenia uprawnień jako jawny fallback. Na tej maszynie kernel ETW nie jest dostępny przy aktualnych prawach; Microsoft opisuje wymagania administratora/`Performance Log Users` dla sesji ETW oraz dodatkowe jawne uprawnienia do sesji SystemTraceProvider. Nie nadawać ich po cichu. Event-driven kolektor może być osobnym, świadomie skonfigurowanym wariantem z kontrolowanym ACL i fallbackiem. Nie używać TLS MITM/WFP ani nie podnosić uprawnień domyślnie.
5. **Zależności:** wspólny `SecurityEvent`, ograniczona kolejka, Windows 10/11 x64, testy w Windows; dostęp do sesji/providera ETW musi być jawnie przyznany i zweryfikowany. Zob. [ETW session control](https://learn.microsoft.com/en-us/windows/win32/etw/controlling-event-tracing-sessions) i [SystemTraceProvider permissions](https://learn.microsoft.com/en-us/windows/win32/etw/configuring-and-starting-a-systemtraceprovider-session).
6. **Etapy:** (a) prototyp kolektora i benchmark; (b) test mapowania PID na proces; (c) deduplikacja/limity; (d) polityka pause/retencji; (e) test utraty źródła i restartu.
7. **Pliki:** `src/Sentinel.Engine/`, nowe `src/Sentinel.Core/Monitoring/`, testy `tests/Sentinel.Tests/`, IPC `desktop/electron/main.cjs`, UI `desktop/src/main.tsx`.
8. **Prywatność:** wyłącznie IP/port/czas/PID/nazwa pliku w minimalnym zakresie; nie przechowywać payloadów/URL; lokalna retencja i jawny opt-in.
9. **Testy:** Windows IP Helper test sprawdza PID żywego TCP listenera i UDP endpointu. Test jednostkowy kolektora weryfikuje zapis nowego lokalnego UDP endpointu oraz zastrzeżenie, że nie dowodzi datagramu. IPC test potomka weryfikuje zdarzenie start/stop. Integracyjny test wstrzykuje 10 500 PID; kolektor ogranicza próbkę do 10 000 PID, zapis do 100 zdarzeń i poprawnie raportuje pominięcia. Testy niepełnych próbek procesów obejmują stabilny wybór, brak fałszywych zdarzeń, restart, stan metadanych bez różnic baseline'u i migrację v13→v14. Test sieci symuluje obcięcie TCP, zmianę zestawu, restart i pełną próbkę; migracja v14→v15 zachowuje endpointy. Osobny test wymusza awarię źródła i weryfikuje odzyskanie. Test live tworzy kontrolowany listener na interfejsie nie-loopback i potwierdza zapis nowego połączenia po baseline. Test korelacji jest informacyjny. Profil TCP `scripts/benchmark-engine.cjs --duration=300 --tcp-monitor` zebrał 60 próbek co 5 s: CPU silnika 0,056% łącznej mocy logicznych procesorów, working set 45,2 MiB na starcie / 57 MiB maksimum, `collect` mediana 5,6 ms / max 675,9 ms; observer pozostał aktywny, kontrolowane połączenie i 13 zdarzeń TCP zapisano bez pominiętych zmian. To pojedyncza sesja lokalna, nie gwarancja długotrwała ani pomiar pod sztucznym obciążeniem.
10. **Akceptacja:** snapshot pokazuje protokół/adresy/PID/nazwę gdy można; próbkowanie procesów tworzy informacyjne start/stop z PID, respektuje pause/wykluczenia, ogranicza snapshot do 10 000 PID i zapis do 100 zmian oraz raportuje liczbę pominiętych; UI ujawnia ograniczenia; brak blokowania. Krótkie procesy mogą zostać pominięte.
11. **Ryzyka:** snapshoty mogą pominąć połączenia krótkie; ETW zależy od wersji i uprawnień; VPN/TLS ograniczają widoczność.
12. **Status:** `IN_PROGRESS` — natywny snapshot TCP/UDP, trwałe baseline'y i korelacja w oknie 60 s są wdrożone; procesy są deterministycznie przycinane do 10 000 PID, a stan obcięcia jest trwały w SQLite v14; tabele TCP/UDP do 800/200 wprowadzają stabilny wybór, trwałe flagi SQLite v15 i wstrzymanie niepewnych alertów. Dla procesu commit `484126f` i Windows CI `39619932040` PASS. Nowa poprawka sieci jest walidowana lokalnie: .NET 213/213, `scripts/build-user.ps1 -Installer` PASS, serwer 22/22 PASS; CI dla tej poprawki oczekuje. Krótkie zdarzenia nadal mogą zostać pominięte; endpoint UDP nie dowodzi transferu. WMI i próba sesji kernel ETW zwróciły `Access denied`; event stream wymaga jawnie przyznanego dostępu systemowego. Pozostają gwarantowany event stream, event-driven korelacja i obsługa krótkich zdarzeń.
