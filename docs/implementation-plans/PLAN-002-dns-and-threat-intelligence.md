# PLAN-002 — DNS i threat intelligence

1. **Cel:** jasno raportować świeżość źródeł i wiarygodne zdarzenia DNS/reputacji z mierzalnym opóźnieniem.
2. **Stan obecny:** `DomainReputation` importuje feed CERT ręcznie do SQLite, obsługuje normalizację, 48 h i rollback; `collect` odczytuje cache Windows przez `ipconfig /displaydns` co 15–300 s, bez podnoszenia uprawnień. Parser normalizuje nazwy, odrzuca metadane i ogranicza wynik do 2000 wpisów. Test Windows-live wykonał cache read na zwykłym koncie; wcześniejszy `Get-DnsClientCache` zwracał `Access denied`.
3. **Braki:** cache nie daje PID/timestamp zapytania; nie ma IP feedu ani URLhaus. Parser i czytnik zdarzeń DNS Client Query Completed (3008) są wdrożone, ale kanał `Microsoft-Windows-DNS-Client/Operational` jest wyłączony na maszynie audytu; pełny odczyt zdarzeń można zweryfikować dopiero po jego świadomym włączeniu w kontrolowanym Windows. Włączenia nie wykonano.
4. **Decyzje:** utrzymać ręczne, stałe źródło. Wpis CERT dopasowuje dokładną domenę oraz jej subdomeny wyłącznie na granicy etykiet; nie dopasowuje domeny nadrzędnej ani podobnie nazwanych hostów. Wpis równy publicznemu sufiksowi nie obejmuje jego tenantów. Odróżnić pustą bazę od świeżej; odczytywać DNS Client Operational tylko wtedy, gdy kanał jest już włączony; nie klasyfikować na podstawie wieku/nazwy. Nie zmieniać konfiguracji systemu ani nie wymagać admina po cichu.
5. **Zależności:** schemat zdarzeń, licencje źródeł, Internet tylko przy jawnej aktualizacji, Windows event source.
6. **Etapy:** (a) status feedu `never_loaded/active/stale/error`; (b) diagnostyka czasu/ostatniego błędu; (c) fixture feedów walidacji; (d) parser 3008, bounded `wevtutil` reader, kursor SQLite v22, status wyłączonego kanału i brak zapisu `QueryResults` — wdrożone; pełna walidacja przy włączonym kanale pozostaje; (e) osobna decyzja o IP feedach.
7. **Pliki:** `DomainReputation.cs`, `Sentinel.Engine/Program.cs`, UI, testy reputation/engine, dokumentacja pokrycia.
8. **Prywatność:** feed pobierany z hosta CERT widzi IP klienta; analizowane URL nie są wysyłane; historia przechowuje tylko domenę wykrycia w ograniczonym przypadku.
9. **Testy:** 0/1/duplikat/niepoprawny feed, wygasły zegar, rollback, offline, kontrolowana domena `.test`, cache bez dopasowania i z nim, timeout/limity. Syntetyczne XML testy potwierdzają filtr dostawcy/kanału/EventID, kursor, odrzucenie IP/niepoprawnych nazw, limit i brak przechowania odpowiedzi; testy SQLite sprawdzają trwałość kursora i migrację v21→v22. Windows-live potwierdził odczyt cache oraz że wyłączony kanał daje jawny fallback bez zmiany konfiguracji.
10. **Akceptacja:** pusty feed nie jest „aktualny”; awaria jawna; poprawna atomowość/rollback; udokumentowany udział cache/Operational i brak claimów pełnego DNS.
11. **Ryzyka:** DoH/DoT/VPN/krótki TTL omijają; ETW nie zobaczy resolvera aplikacyjnego/DoH; CERT jest ograniczonym źródłem.
12. **Status:** `IN_PROGRESS` — podstawowy feed i polling zweryfikowane; dopasowanie host/subdomena zgodne z regułą CERT ma testy Core, a pełna bramka dla aktualnego commita przeszła .NET 320/320, Engine IPC/DNS/TCP/UDP, Electron 16/16, `npm audit` 0, UI build i installer self-test. Pusty feed nie jest przedstawiany jako aktualny. Status Engine, UI i pakiet diagnostyczny pokazują stan odczytu cache oraz DNS Operational. Parser/reader są testowane syntetycznie i przez Windows fallback; odczyt działa tylko dla już włączonego kanału. Na maszynie audytu kanału nie włączano, więc live odczyt zdarzeń pozostaje niezweryfikowany. Pominięcia DoH/DoT/VPN i brak IP feeds pozostają. Schemat zdarzenia 3008 potwierdzono przez provider metadata; Microsoft opisuje jego użycie w [regułach WEF](https://learn.microsoft.com/en-us/windows/security/threat-protection/use-windows-event-forwarding-to-assist-with-intrusion-detection), a składnię read-only `wevtutil qe/gl` w [dokumentacji Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/wevtutil).
13. **Odporność kursora (2026-10-23):** jeżeli maksymalny EventRecordID jest niższy od zapisanego kursora, odczyt wznawia się od zera w bieżącym logu, a EventId deterministycznie uwzględnia czas, nazwę zapytania, typ i status. Testy sprawdzają normalny przyrost, reset, powtarzalność ID i rozróżnienie rekordów po resecie. Na maszynie audytu kanał pozostaje wyłączony, więc pełny reader nie został przetestowany na żywych zdarzeniach.
14. **Dopasowanie CERT (2026-10-23):** `Contains` i `FindMatches` sprawdzają wpis hosta oraz jego nadrzędne sufiksy na granicach etykiet, aż do domeny rejestrowalnej; testy pokrywają subdomenę, brak dopasowania domeny nadrzędnej, lookalike i wpis `co.uk`. CERT zaleca blokować też subdomeny wpisu, ale nie jego domenę nadrzędną ([lista ostrzeżeń CERT Polska](https://cert.pl/lista-ostrzezen/)). Pełna bramka przeszła: .NET 320/320 bez pominięć, Engine IPC/DNS/TCP/UDP, Electron 16/16, `npm audit` 0, UI production build i installer self-test.
