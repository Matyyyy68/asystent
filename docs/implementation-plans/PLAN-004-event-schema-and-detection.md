# PLAN-004 — wspólny model zdarzeń i detekcja

1. **Cel:** wersjonowane, testowalne zdarzenie wspólne dla ręcznych reguł, DNS, browsera, plików i przyszłego Enterprise.
2. **Stan obecny:** lokalny `SecurityEvent` i Enterprise DTO mają różne zakresy, ale wspólny transportowy kontrakt `EnterpriseEventV1` oraz batch/result w `src/Sentinel.Contracts` są współdzielone przez klienta i serwer. Wspólny walidator pilnuje ID, czasu, kategorii, ryzyka, kodu reguły, źródła i wersji schematu.
3. **Braki:** deduplikacja między odrębnymi modułami oraz strukturalne evidence/confidence. Jawne `eventId` deduplikuje ponowiony zapis lokalny od v0.15.31; zdarzenia bez identyfikatora nadal dostają nowy GUID. Kandydat v0.15.34 dodaje ograniczone korelowanie startu procesu z TCP/UDP (zgodny PID i nazwa, 60 s), ale DNS/przeglądarka/pliki nie są łączone, a duplikaty nie są scalane. Lokalny adapter mapuje kategorię na Enterprise heurystycznie; batch, w którym to samo ID powtarza się w ramach jednej transakcji, nadal jest odrzucany atomowo.
4. **Decyzje:** additive SQLite migration; tekst prywatny/pełny URL pozostaje wyłączony; confidence oddzielone od ryzyka; wartości nieznane nie są wymuszane.
5. **Zależności:** `LocalStore`, kontrakt server API v1 (kompatybilność), retencja/eksport, klient Electron.
6. **Etapy:** (a) wspólny kontrakt v1 i walidator — wykonano; (b) migracja i test legacy db — wykonano; (c) adapter starych zdarzeń — częściowo; (d) `ruleVersion/source/evidence codes` — źródło/wersja wykonane; (e) idempotencja/status false positive wykonane; korelacja process-to-network jest w kandydacie v0.15.34; deduplikacja cross-source i grupowanie innych źródeł pozostają; (f) adapter Enterprise — używa współdzielonego DTO, kategoryzacja pozostaje heurystyczna.
7. **Pliki:** `src/Sentinel.Contracts/EnterpriseEventV1.cs`, `Models.cs`, `LocalStore.cs`, `Sentinel.Engine/Program.cs`, serwerowe `SecurityEvents.cs`, testy Core/API, renderer.
8. **Prywatność:** bez treści, haseł, pełnych URL i ekranu; `evidence` ograniczone do kodów/przesłanek redagowanych; retention.
9. **Testy:** migracja starych baz, brak utraty historii, enum/version validation, idempotence, retencja, eksport redaction, cross-contract fixtures.
10. **Akceptacja:** wszystkie nowe źródła zapisują v1 zdarzenia; legacy odczyt działa; false positive i source są widoczne; feed/API nie przyjmują nadmiarowych pól.
11. **Ryzyka:** migracje i zgodność z istniejącymi danymi; schemat API wymaga wersjonowania.
12. **Status:** `IN_PROGRESS` — opublikowane v0.15.33 współdzieli DTO, batch/result i walidację przez `Sentinel.Contracts`. Kandydat v0.15.34 dodaje correlationId dla startu procesu i TCP/UDP z tym samym PID/nazwą w 60 s, migrację SQLite v10→v11, zachowanie ID w eksporcie/kopiach i etykietę czasowej grupy w UI. Lokalnie .NET 195/195, testy serwera 20/20, Release server build, HTTP smoke i desktop test/lint/build PASS; self-test instalatora PASS (279352697 B, SHA-256 `18931A566F82CE34459E4C0450D147ECE43DC54328274924D70761CC633D17C3`). Nadal brakuje deduplikacji między źródłami, korelacji DNS/przeglądarki/plików oraz strukturalnych evidence/confidence i jawnego mapowania kategorii. Confidence pozostaje puste bez kalibracji.
