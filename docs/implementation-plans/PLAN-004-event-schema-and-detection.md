# PLAN-004 — wspólny model zdarzeń i detekcja

1. **Cel:** wersjonowane, testowalne zdarzenie wspólne dla ręcznych reguł, DNS, browsera, plików i przyszłego Enterprise.
2. **Stan obecny:** lokalny `SecurityEvent` i Enterprise DTO mają różne zakresy, ale wspólny transportowy kontrakt `EnterpriseEventV1` oraz batch/result w `src/Sentinel.Contracts` są współdzielone przez klienta i serwer. Wspólny walidator pilnuje ID, czasu, kategorii, ryzyka, kodu reguły, źródła i wersji schematu.
3. **Braki:** deduplikacja między odrębnymi modułami oraz kalibracja confidence. Jawne `eventId` deduplikuje ponowiony zapis lokalny od v0.15.31; zdarzenia bez identyfikatora nadal dostają nowy GUID. Wydanie v0.15.34 dodaje ograniczone korelowanie startu procesu z TCP/UDP (zgodny PID i nazwa, 60 s), ale DNS/przeglądarka/pliki nie są łączone, a duplikaty nie są scalane. Lokalny adapter mapuje kategorię na Enterprise heurystycznie; batch, w którym to samo ID powtarza się w ramach jednej transakcji, nadal jest odrzucany atomowo.
4. **Decyzje:** additive SQLite migration; tekst prywatny/pełny URL pozostaje wyłączony; confidence oddzielone od ryzyka; wartości nieznane nie są wymuszane.
5. **Zależności:** `LocalStore`, kontrakt server API v1 (kompatybilność), retencja/eksport, klient Electron.
6. **Etapy:** (a) wspólny kontrakt v1 i walidator — wykonano; (b) migracja i test legacy db — wykonano; (c) adapter starych zdarzeń — częściowo; (d) `ruleVersion/source/evidence codes` — źródło, wersja i walidowane kody dowodowe wykonane w kandydacie v0.15.35; (e) idempotencja/status false positive wykonane; korelacja process-to-network działa w v0.15.34; wydanie v0.15.37 dodaje czasowe grupowanie po domenie, a v0.15.38 utrwala URL evidence codes dla browser-extension, aby wyjaśnienie wspólnej grupy w UI poprawnie odróżniało korelację domeny od korelacji procesu; deduplikacja cross-source i korelacja plików pozostają; (f) adapter Enterprise — używa współdzielonego DTO, kategoryzacja pozostaje heurystyczna.
7. **Pliki:** `src/Sentinel.Contracts/EnterpriseEventV1.cs`, `Models.cs`, `LocalStore.cs`, `Sentinel.Engine/Program.cs`, serwerowe `SecurityEvents.cs`, testy Core/API, renderer.
8. **Prywatność:** bez treści, haseł, pełnych URL i ekranu; `evidence` ograniczone do kodów/przesłanek redagowanych; retention.
9. **Testy:** migracja starych baz, brak utraty historii, enum/version validation, idempotence, retencja, eksport redaction, cross-contract fixtures.
10. **Akceptacja:** wszystkie nowe źródła zapisują v1 zdarzenia; legacy odczyt działa; false positive i source są widoczne; feed/API nie przyjmują nadmiarowych pól.
11. **Ryzyka:** migracje i zgodność z istniejącymi danymi; schemat API wymaga wersjonowania.
12. **Status:** `IN_PROGRESS` — wspólny kontrakt Enterprise, walidacja, migracje SQLite, eksport/restore oraz evidence codes są wdrożone. v0.15.34 koreluje czasowo start procesu i TCP/UDP o zgodnym PID/nazwie; v0.15.37 grupuje czasowo DNS, rozszerzenie i ręczny URL przez hash domeny; v0.15.38 zachowuje kody przesłanek przeglądarki, by UI objaśniało źródło grupy. Lokalna walidacja późniejszego kodu z cytatami FTS5: .NET 207/207, Engine IPC, desktop 6/6, UI build i installer self-test PASS; Windows CI dla commita `185c62f` PASS (`39503611778`). Windows CI dla bieżącego funkcjonalnego commita `79668a4` także PASS (`39505227855`). Nadal brakuje deduplikacji między źródłami, korelacji plików, skalibrowanego confidence i jawnego mapowania kategorii. Confidence pozostaje puste bez kalibracji.
