# Prywatność i bezpieczeństwo

Domyślny silnik oraz historia pracują lokalnie. W nowym profilu procesy, Downloads, wybrane zmiany trwałości Windows i metadane połączeń TCP/UDP są monitorowane lokalnie bez przesyłania. Istniejące zapisane preferencje użytkownika pozostają zachowane. SQLite nie jest szyfrowana; zależnie od monitora mogą być lokalnie zapisywane nazwy/identyfikatory procesów, ścieżki, rozmiary, czasy, hashe i metadane zdarzeń. Zbieranie tekstu aktywnego okna pozostaje wyłączone. Nowe profile automatycznie pobierają raz na 24 godziny stały feed domen CERT Polska przez HTTPS; zapytanie nie zawiera sprawdzanych adresów ani innych danych użytkownika. Pozostałe feedy zewnętrzne nie są pobierane automatycznie. Eksporty oraz Enterprise mają osobne filtrowanie. Wysyłanie metadanych do Enterprise wymaga jawnej zgody; ręczne wysłanie treści do Enterprise wymaga osobnego natywnego potwierdzenia. MalwareBazaar lookup wysyła hash po osobnym działaniu i wymaga klucza.

Pierwsza analiza odczytuje nazwę, wersję i wydawcę aplikacji z rejestru Windows. Spis pozostaje w pamięci silnika i jest zwracany wyłącznie lokalnemu UI po osobnym kliknięciu; nie trafia do historii, eksportu ani Enterprise. Ścieżki instalacji i polecenia deinstalacji nie są odczytywane. Spis nie służy do oceny CVE.

Sentinel nie zbiera haseł, nie rejestruje klawiatury, nie nagrywa ekranu i nie odszyfrowuje HTTPS. Nie wyłącza Microsoft Defender. Nie usuwa plików automatycznie na podstawie niepewnego wyniku. Po osobnym potwierdzeniu użytkownik może przenieść wybrany plik z Downloads do lokalnej kwarantanny, jeśli jego ponownie obliczony SHA-256 odpowiada zdarzeniu opartemu na ręcznie zaimportowanej liście. Plik i lokalna baza `quarantine.db` (z nazwą, pierwotną ścieżką i hashem) pozostają na urządzeniu i nie są szyfrowane ani dołączane do kopii samej historii SQLite. Przywrócenie ponownie weryfikuje hash i nie nadpisuje istniejącego pliku. Usługa z uprawnieniami SYSTEM nie istnieje.

Odczyt Windows Security Center jest lokalny i tylko do odczytu; zgłasza zagregowany stan kategorii antywirusa/zapory, nie nazwę konkretnego produktu.

Engine co 5 minut wywołuje wbudowany cmdlet `Get-MpComputerStatus` bez parametrów zmieniających stan, aby odczytać własny stan Defendera i wersję/czas sygnatur; po odmowie lub błędzie ponawia najwcześniej za 15 minut. Zapytanie jest ograniczone do 4 sekund, uruchamiane bez profilu PowerShell i nie wysyła danych. Na środowisku bieżącego testu WMI zwróciło `Access denied` dla niepodniesionego procesu, więc UI poprawnie pokaże stan szczegółowy jako niedostępny. Nie żądamy podniesienia uprawnień ani nie wyciągamy z tego wniosku, że nie działa inny antywirus.

Zakres, retencję i ograniczenia każdego źródła opisuje [monitorowanie Windows](WINDOWS_MONITORING.md) oraz [znane ograniczenia](KNOWN-LIMITATIONS.md).
